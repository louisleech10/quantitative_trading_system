## 🔴 P0 - 關鍵優化（Critical）

### P0-001: 並發寫入安全性

**狀態**: ⏳ 待處理  
**預計工時**: 2-3 天  
**負責人**: TBD  
**目標日期**: Phase 4 完成後

#### 問題描述
目前 HDF5 檔案不支援多進程同時寫入，在批量下載或並行處理時可能造成：
- 數據損壞或遺失
- 檔案鎖定衝突
- 部分寫入失敗

#### 優化原因
- **風險等級**: 極高 - 數據損壞影響整個 ML 訓練流程
- **發生機率**: 中等 - 批量下載時可能觸發
- **影響範圍**: 所有依賴 HDF5 的功能

#### 優化目的
1. 防止數據損壞和遺失
2. 確保批量下載的可靠性
3. 支援未來的並行處理需求

#### 建議方向

**方案 A: 分散式檔案鎖（推薦）**
```python
# 使用 filelock 函式庫
from filelock import FileLock

def write_klines_safe(self, symbol, timeframe, df):
    """線程安全的寫入"""
    lock_path = self.cache_dir / f".{symbol}_{timeframe}.lock"
    
    with FileLock(lock_path, timeout=30):
        return self.write_klines(symbol, timeframe, df)
```

**方案 B: 寫入佇列系統**
```python
# 使用單一寫入進程 + 任務佇列
class HDF5WriteQueue:
    def __init__(self):
        self.queue = asyncio.Queue()
        self.writer_task = asyncio.create_task(self._writer_loop())
    
    async def write(self, symbol, timeframe, df):
        await self.queue.put((symbol, timeframe, df))
    
    async def _writer_loop(self):
        while True:
            symbol, timeframe, df = await self.queue.get()
            self.storage.write_klines(symbol, timeframe, df)
```

**方案 C: 每個 symbol 獨立檔案**
- 優點: 天然隔離，無需鎖機制
- 缺點: 檔案數量暴增（430+ 檔案）

- [ ] 並發寫入測試通過（10 個進程同時寫入）
- [ ] 無數據損壞（完整性驗證）
- [ ] 無死鎖（壓力測試 1 小時）
- [ ] 性能影響 < 10%

1. 識別並標記維護期間的缺口

#### 建議方向

**實作內容**:

```python
def validate_continuity_with_maintenance_check(
    df: pd.DataFrame,
    symbol: str,
    timeframe: str,
    maintenance_periods: List[MaintenancePeriod]
):
    """連續性驗證（排除維護期間）"""

        raise ValueError(
            f"發現 {len(real_gaps)} 個非維護期間的缺口"
        )
    
    # 記錄維護期間缺口（INFO 級別）
    if maintenance_gaps:

            f"{symbol}/{timeframe} 在維護期間有 {len(maintenance_gaps)} 個合法缺口"
        )
```

### P1-005: 幣種生命週期管理

#### 問題描述

- **誤報**: 上架前的時間範圍被視為數據缺失
- **查詢失敗**: 無法正確限制查詢範圍

#### 優化目的
1. 自動調整查詢範圍到有效期間

3. 提供幣種生命週期查詢 API

```python
class TransactionalHDF5Writer:
    """支援事務的 HDF5 寫入器"""
    
    def write_with_transaction(self, symbol, timeframe, df):
        """事務性寫入"""
        
        # 建立臨時檔案
        temp_path = self.get_temp_path(symbol, timeframe)
        backup_path = self.get_backup_path(symbol, timeframe)
        target_path = self.get_target_path(symbol, timeframe)
        
        try:
            # 階段 1: 備份現有檔案

            # 階段 2: 寫入到臨時檔案

            # 階段 4: 原子性替換
```

```python
# 1. 智能重試策略
class SmartRetryStrategy:
    """智能重試策略"""
    
    def __init__(self):
        self.weight_tracker = {}  # 追蹤每個端點的權重使用
        self.rate_limit_reset_time = {}  # 限流重置時間
    
    async def execute_with_retry(self, func, *args, **kwargs):
        """帶智能重試的執行"""
        
        max_retries = 5
        base_delay = 1  # 基礎延遲 1 秒
        
        for attempt in range(max_retries):
            try:
                # 檢查是否在限流期間
                if self.is_rate_limited():
                    wait_time = self.get_rate_limit_wait_time()
                    logger.warning(
                        f"API 限流中，等待 {wait_time} 秒後重試"
                    )
                    await asyncio.sleep(wait_time)
                
                # 執行請求
                result = await func(*args, **kwargs)
                
                # 更新權重使用
                self.update_weight_usage(result)
                
                return result
                
            except RateLimitError as e:
                # 從 header 獲取重置時間
                reset_time = e.response.headers.get('X-MBX-USED-WEIGHT-1M')
                if reset_time:
                    self.rate_limit_reset_time = int(reset_time)
                
                # 指數退避 + 抖動
                delay = base_delay * (2 ** attempt) + random.uniform(0, 1)
                
                logger.warning(
                    f"遇到 API 限流 (嘗試 {attempt+1}/{max_retries})\n"
                    f"  等待 {delay:.1f} 秒後重試"
                )
                
                await asyncio.sleep(delay)
            
            except Exception as e:
                # 其他錯誤 - 不重試
                logger.error(f"請求失敗: {e}")
                raise
        
        # 達到最大重試次數
        raise MaxRetriesExceededError(
            f"達到最大重試次數 ({max_retries})"
        )
    
    def is_rate_limited(self):
        """檢查是否在限流期間"""
        if not self.rate_limit_reset_time:
            return False
        
        return time.time() < self.rate_limit_reset_time
    
    def get_rate_limit_wait_time(self):
        """獲取需要等待的時間"""
        return max(0, self.rate_limit_reset_time - time.time())
    
    def update_weight_usage(self, response):
        """更新權重使用情況"""
        weight_used = response.headers.get('X-MBX-USED-WEIGHT-1M')
        weight_limit = response.headers.get('X-MBX-ORDER-COUNT-1M')
        
        if weight_used and weight_limit:
            usage_percent = int(weight_used) / int(weight_limit) * 100
            
            if usage_percent > 80:
                logger.warning(
                    f"⚠️ API 權重使用接近限制: {usage_percent:.1f}%"
                )
            
            # 動態調整請求速度
            if usage_percent > 90:
                # 接近限制 - 大幅減速
                self.request_delay = 5.0
            elif usage_percent > 70:
                # 使用較多 - 適度減速
                self.request_delay = 2.0
            else:
                # 正常使用
                self.request_delay = 0.5
```

```python
class DiskSpaceMonitor:
    """磁碟空間監控"""
    
    def __init__(self, data_dir: Path, min_free_gb: int = 10):
        self.data_dir = data_dir
        self.min_free_gb = min_free_gb
    
    def get_disk_usage(self):
        """獲取磁碟使用情況"""
        import shutil
        
        usage = shutil.disk_usage(self.data_dir)
        
        return {
            "total_gb": usage.total / (1024**3),
            "used_gb": usage.used / (1024**3),
            "free_gb": usage.free / (1024**3),
            "usage_percent": (usage.used / usage.total) * 100
        }
```

### P2-006: HDF5 檔案完整性定期驗證

**狀態**: ⏳ 待處理  
**預計工時**: 2 天  
**負責人**: TBD  
**目標日期**: Phase 4 完成後

#### 問題描述
HDF5 檔案可能因異常關機、磁碟錯誤等原因損壞，目前只在讀取時才發現。

#### 優化原因
- **被動發現**: 使用時才發現損壞
- **影響範圍大**: 檔案損壞影響該 symbol 所有功能
- **恢復困難**: 不確定何時開始損壞

#### 優化目的
1. 定期驗證檔案完整性
2. 提前發現損壞問題
3. 自動備份與恢復

#### 建議方向

**實作內容**:
```python
# 1. 完整性驗證
class HDF5IntegrityChecker:
    """HDF5 檔案完整性檢查器"""
    
    def verify_file(self, hdf5_path: Path) -> Dict:
        """驗證單個 HDF5 檔案"""
        
        result = {
            "file": str(hdf5_path),
            "status": "unknown",
            "issues": [],
            "checked_at": datetime.now()
        }
        
        try:
            # 測試 1: 檔案可開啟
            with h5py.File(hdf5_path, 'r') as f:
                
                # 測試 2: 讀取所有 group
                for group_name in f.keys():
                    group = f[group_name]
                    
                    # 測試 3: 讀取所有 dataset
                    for dataset_name in group.keys():
                        try:
                            dataset = group[dataset_name]
                            data = dataset[:]  # 讀取全部數據
                            
                            # 測試 4: 驗證數據格式
                            df = pd.DataFrame(data)
                            
                            # 測試 5: 時間戳驗證
                            if 'timestamp' in df.columns:
                                if not df['timestamp'].is_monotonic_increasing:
                                    result["issues"].append({
                                        "severity": "error",
                                        "message": f"{group_name}/{dataset_name}: 時間戳非單調遞增"
                                    })
                            
                            # 測試 6: 檢查 NaN 值
                            nan_count = df.isna().sum().sum()
                            if nan_count > 0:
                                result["issues"].append({
                                    "severity": "warning",
                                    "message": f"{group_name}/{dataset_name}: 發現 {nan_count} 個 NaN 值"
                                })
                        
                        except Exception as e:
                            result["issues"].append({
                                "severity": "error",
                                "message": f"{group_name}/{dataset_name}: 讀取失敗 - {str(e)}"
                            })
            
            # 判定狀態
            if len([i for i in result["issues"] if i["severity"] == "error"]) > 0:
                result["status"] = "corrupted"
            elif len([i for i in result["issues"] if i["severity"] == "warning"]) > 0:
                result["status"] = "warning"
            else:
                result["status"] = "healthy"
        
        except Exception as e:
            result["status"] = "corrupted"
            result["issues"].append({
                "severity": "critical",
                "message": f"無法開啟檔案: {str(e)}"
            })
        
        return result
    
    def batch_verify(self, data_dir: Path) -> Dict:
        """批量驗證所有 HDF5 檔案"""
        
        results = {
            "total_files": 0,
            "healthy": 0,
            "warning": 0,
            "corrupted": 0,
            "details": []
        }
        
        for hdf5_file in data_dir.glob("*.h5"):
            result = self.verify_file(hdf5_file)
            results["total_files"] += 1
            results[result["status"]] += 1
            
            # 只記錄有問題的檔案
            if result["status"] != "healthy":
                results["details"].append(result)
        
        return results

# 2. 自動備份與恢復
class HDF5BackupManager:
    """HDF5 備份管理"""
    
    def create_backup(self, hdf5_path: Path):
        """建立備份"""
        
        backup_dir = hdf5_path.parent / "backups"
        backup_dir.mkdir(exist_ok=True)
        
        timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
        backup_path = backup_dir / f"{hdf5_path.stem}_{timestamp}.h5"
        
        shutil.copy2(hdf5_path, backup_path)
        
        logger.info(f"✅ 備份建立: {backup_path}")
        
        # 清理舊備份（保留最近 7 天）
        self.cleanup_old_backups(backup_dir, days=7)
    
    def restore_from_backup(self, hdf5_path: Path):
        """從最新備份恢復"""
        
        backup_dir = hdf5_path.parent / "backups"
        backups = sorted(
            backup_dir.glob(f"{hdf5_path.stem}_*.h5"),
            key=lambda p: p.stat().st_mtime,
            reverse=True
        )
        
        if not backups:
            raise FileNotFoundError("無可用的備份檔案")
        
        latest_backup = backups[0]
        shutil.copy2(latest_backup, hdf5_path)
        
        logger.info(f"✅ 已從備份恢復: {latest_backup} → {hdf5_path}")

# 3. 定期檢查任務
@scheduler.scheduled_job('cron', hour=3, minute=0)  # 每天凌晨 3 點
async def daily_integrity_check():
    """定期完整性檢查"""
    
    checker = HDF5IntegrityChecker()
    results = checker.batch_verify(DATA_CACHE_DIR)
    
    logger.info(
        f"HDF5 完整性檢查完成:\n"
        f"  總檔案: {results['total_files']}\n"
        f"  健康: {results['healthy']}\n"
        f"  警告: {results['warning']}\n"
        f"  損壞: {results['corrupted']}"
    )
    
    # 損壞檔案自動恢復
    if results['corrupted'] > 0:
        backup_manager = HDF5BackupManager()
        
        for detail in results['details']:
            if detail['status'] == 'corrupted':
                try:
                    backup_manager.restore_from_backup(Path(detail['file']))
                    logger.info(f"✅ 自動恢復成功: {detail['file']}")
                except Exception as e:
                    logger.error(f"❌ 自動恢復失敗: {detail['file']} - {e}")
                    # 發送警報
                    send_alert(f"HDF5 檔案損壞且無法恢復: {detail['file']}")
```

- [ ] 檢查報告可查詢
- [ ] 無法恢復時發送警報

### P3-001: Toast 通知持續時間動態調整

**狀態**: ⏳ 待處理  
**預計工時**: 0.5 天  
**負責人**: TBD

#### 問題描述
Toast 通知固定顯示 5 秒，長錯誤訊息讀不完就消失。

#### 優化原因

- **訊息遺失**: 使用者可能錯過重要資訊

#### 優化目的
根據訊息長度動態調整顯示時間

#### 建議方向

```typescript
function showToast(message: string, type: 'success' | 'error' | 'info') {
  const baseTime = 3000;  // 基礎 3 秒
  const charTime = 50;    // 每字 50 毫秒
  
  // 計算持續時間（最少 3 秒，最多 15 秒）
  const duration = Math.min(
    Math.max(baseTime, message.length * charTime),
    15000
  );
  
  toast[type](message, { duration });
}
```

#### 驗證標準
- [ ] 短訊息 3-5 秒
- [ ] 長訊息 10-15 秒
- [ ] 不超過 15 秒

```python
def normalize_timestamp(timestamps: np.ndarray) -> np.ndarray:
    """統一時間戳精度"""
    
    # 偵測精度（秒 vs 毫秒）
    if timestamps[0] > 1e12:
        # 毫秒級 - 轉換為秒
        logger.warning("偵測到毫秒級時間戳，自動轉換為秒")
        timestamps = timestamps / 1000
    
    return timestamps
```
