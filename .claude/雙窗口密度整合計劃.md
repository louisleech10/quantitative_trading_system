```python
Phase 3.2 雙窗口密度計算驗證

驗證方法:
- 使用真實案例數據（165個案例：55正例 + 110反例）

6. 驗證邊界情況
7. 生成 CSV 輸出
```

### 驗證成功標準

✅ **必須滿足**:
- 所有165個案例計算成功（無異常）
- 無除零錯誤
- 近期窗口大小 = lookback_bars (24根)
- 遠期窗口大小 = far_lookback_bars - lookback_bars (76根)
- 窗口無重疊（遠期窗口不包含近期窗口）

✅ **期望結果**:
- ratio_separation > 0（正例 ratio > 反例 ratio）
- p_value < 0.05（統計顯著）
- CSV 輸出完整且格式正確

⚠️ **注意事項**:
- 如果 ratio_separation < 0，需要檢查策略邏輯是否正確
- 如果有大量 NaN 值，需要檢查 K線數據完整性
- 如果計算失敗率 > 5%，需要檢查數據質量

## 🎨 階段二：UI/UX 重新設計與整合

### 背景分析

**現狀問題**:
1. strategy-test 和 strategy-demo 頁面功能重複

```tsx
// frontend/src/components/ui/Accordion.tsx
interface AccordionProps {
  children: React.ReactNode;
  defaultExpanded?: string[]; // 預設展開的項目 ID
  allowMultiple?: boolean;     // 允許多個項目同時展開
}

export function Accordion({ children, defaultExpanded, allowMultiple }: AccordionProps) {
  const [expanded, setExpanded] = useState<string[]>(defaultExpanded || []);

  const toggleItem = (id: string) => {
    if (allowMultiple) {
      setExpanded(prev =>
        prev.includes(id) ? prev.filter(i => i !== id) : [...prev, id]
      );
    } else {
      setExpanded(prev => prev.includes(id) ? [] : [id]);
    }
  };

  return (
    <div className="space-y-2">
      {React.Children.map(children, child => {
        if (React.isValidElement(child)) {
          return React.cloneElement(child, {
            expanded: expanded.includes(child.props.id),
            onToggle: () => toggleItem(child.props.id)
          });
        }
        return child;
      })}
    </div>
  );
}
```

```tsx
interface MultiSelectProps {
  label: string;
  options: Array<{
    value: string;
    label: string;
    icon?: string;
    disabled?: boolean;
  }>;
  value: string[];
  onChange: (value: string[]) => void;
  placeholder?: string;
}

export function MultiSelect({ label, options, value, onChange, placeholder }: MultiSelectProps) {
  const [isOpen, setIsOpen] = useState(false);

  const toggleOption = (optionValue: string) => {
    onChange(
      value.includes(optionValue)
        ? value.filter(v => v !== optionValue)
        : [...value, optionValue]
    );
  };

  return (
    <div className="relative">
      <label>{label}</label>
      <button onClick={() => setIsOpen(!isOpen)}>
        {value.length > 0 ? `${value.length} 項已選` : placeholder}
      </button>

      {isOpen && (
        <div className="absolute z-10 mt-1 w-full bg-white border rounded shadow-lg">
          {options.map(option => (
            <div
              key={option.value}
              className={`flex items-center px-3 py-2 cursor-pointer hover:bg-gray-100 ${
                option.disabled ? 'opacity-50 cursor-not-allowed' : ''
              }`}
              onClick={() => !option.disabled && toggleOption(option.value)}
            >
              <input
                type="checkbox"
                checked={value.includes(option.value)}
                disabled={option.disabled}
                readOnly
                className="mr-2"
              />
              {option.icon && <span className="mr-2">{option.icon}</span>}
              <span>{option.label}</span>
            </div>
          ))}
        </div>
      )}
    </div>
```

```python
# momentum/Optimization/optuna_optimizer.py

def objective(trial):
    """
    Optuna 優化目標函數

    支持兩種模式:
    1. 單密度模式: 優化 separation (positive_avg_density - negative_avg_density)
    2. 雙密度模式: 加權優化 (方案D)
       - clustering_score = positive_near_far_ratio - 1.0 (聚集程度)
       - discrimination_score = ratio_separation (區分度)
       - objective = clustering_weight * clustering_score + (1-clustering_weight) * discrimination_score
    """

    # ... 參數採樣 ...

    # ... 配置窗口參數 ...
    window_config = TrainingWindowConfig(
        reference_point="TO",
        lookback_bars=lookback_bars,
        lookforward_bars=0,
        far_lookback_bars=far_lookback_bars if use_dual_density else None,
        mode="relative"
    )

    # ... 執行密度分析 ...
    result = analyzer.analyze_signal_density(
        positive_cases=positive_cases,
        negative_cases=negative_cases,
        strategy_config=strategy_config,
        window_config=window_config
    )

    # 檢測優化模式
    is_dual_density = (
        window_config.far_lookback_bars is not None
        and result.ratio_separation is not None
    )

    if is_dual_density:
        # 雙密度模式: 加權優化
        clustering_score = result.positive_near_far_ratio - 1.0
        discrimination_score = result.ratio_separation

        objective_value = (
            clustering_weight * clustering_score +
            (1.0 - clustering_weight) * discrimination_score
        )

        logger.info(
            f"Trial {trial.number} [DUAL-DENSITY-WEIGHTED]: "
            f"objective={objective_value:.4f} "
            f"(clustering={clustering_score:.4f} [w={clustering_weight:.2f}], "
            f"discrimination={discrimination_score:.4f} [w={1.0-clustering_weight:.2f}]), "
            f"pos_ratio={result.positive_near_far_ratio:.4f}, "
            f"neg_ratio={result.negative_near_far_ratio:.4f}"
        )
        return objective_value
    else:
        # 單密度模式 (向後兼容)
        logger.info(
            f"Trial {trial.number} [SINGLE-DENSITY]: "
            f"separation={result.separation:.4f}, "
            f"p_value={result.p_value:.6f}"
        )
        return result.separation
```

## ⚠️ 注意事項與風險

### 階段一風險

1. **數據質量問題**
   - 風險: K線數據缺失導致窗口提取失敗
   - 緩解: 添加數據完整性檢查，記錄缺失數據

2. **性能問題**
   - 風險: 165個案例計算時間過長
   - 緩解: 添加進度條，考慮多進程並行計算

3. **結果不符預期**
   - 風險: ratio_separation < 0（反例ratio反而更高）
   - 緩解: 檢查策略邏輯，考慮調整參數或策略

### 階段二風險

1. **UI 組件相容性**
   - 風險: 新組件在不同瀏覽器表現不一致
   - 緩解: 使用成熟的 UI 庫（如 Radix UI, Headless UI）

2. **狀態管理複雜度**
   - 風險: 配置狀態過於複雜，難以維護
   - 緩解: 使用 Context + Reducer 或 Zustand 管理狀態

3. **移動端體驗**
   - 風險: 配置面板在小屏設備難以操作
   - 緩解: 採用底部抽屜式設計，簡化必填項

### 階段三風險

1. **優化目標不穩定**
   - 風險: ratio_separation 波動大，難以收斂
   - 緩解: 增加樣本數量，考慮使用更穩健的優化算法

2. **向後兼容性**
   - 風險: 修改破壞了現有優化流程
   - 緩解: 完整的單元測試，保留原有邏輯路徑

### 階段四風險

1. **架構過度設計**
   - 風險: 為未來功能設計過於複雜，短期無用
   - 緩解: 採用漸進式設計，先實現核心，後擴展

2. **邏輯表達式安全性**
   - 風險: 用戶輸入惡意代碼
   - 緩解: 嚴格的沙箱執行，白名單驗證
