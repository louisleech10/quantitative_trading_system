# 案例搜尋系統：歷史穩定度特徵參數實作規格

## 文檔版本
- **版本**: 1.0  
- **目標**: 新增5個「過去歷史穩定度」特徵參數，用於案例品質過濾  
- **優先原則**: **計算效率優先**（使用向量化操作，避免循環）

---

## 一、功能背景

### 當前問題
現有30個參數只檢查「T時刻狀態」和「T之後表現」，缺少「T之前歷史」檢查，導致：
- **反向案例污染**: 一個時間點T雖然當前bar平穩（±1.5%），但前24hr可能剛經歷+8%波動，技術指標（RSI、MACD）仍處於高位，不適合當作「真正平穩」的反向案例
- **正向案例假突破**: 雖然T bar漲10%，但前48hr已連續上漲15%，可能是趨勢末端而非真正突破

### 解決方案
新增5個參數檢查T時刻**之前的歷史穩定度**，確保：
- 反向案例：T之前一段時間也確實平穩（無大幅波動）
- 正向案例：可選過濾掉趨勢末端的假突破

### 設計原則
1. **時間尺度對應**: 根據timeframe動態調整往前看幾根bar
2. **計算效率優先**: 使用pandas向量化，避免Python循環
3. **參數互補**: 5個參數從不同維度檢查（價格波動、方向性、成交量），避免冗餘

## 二、Timeframe與Bar數量對應表

### 標準時間窗口定義
| 時間窗口 | 含義 | 
|---------|------|
| 24hr | 近期（短期檢測） |
| 48hr | 中期（中期穩定度） |
| 72hr | 長期（整體波動水平） |

### Bar數量對應（關鍵）

| Timeframe | 每根bar時長 | 24hr = X根bar | 48hr = X根bar | 72hr = X根bar |
|-----------|-------------|---------------|---------------|---------------|
| **1h**    | 1小時       | 24根          | 48根          | 72根          |
| **4h**    | 4小時       | 6根           | 12根          | 18根          |
| **12h**   | 12小時      | 2根           | 4根           | 6根           |
| **1d**    | 24小時      | 1根           | 2根           | 3根           |

**計算公式**:
```python
hours_per_candle = timeframe_to_hours(timeframe)  # 1h→1, 4h→4, 12h→12, 1d→24
periods_24hr = 24 // hours_per_candle
periods_48hr = 48 // hours_per_candle
periods_72hr = 72 // hours_per_candle
```

**範例**: 
- 12hr timeframe: `periods_24hr = 24 // 12 = 2根`
- 4hr timeframe: `periods_48hr = 48 // 4 = 12根`

## 三、5個新參數定義

### 參數1: past_24hr_max_single_move
**目的**: 檢測近期是否有劇烈單向波動  
**計算邏輯**: 過去24hr內，所有單根bar中**絕對漲跌幅最大值**

**公式**:
```python
past_24hr_max_single_move = df['return'].rolling(periods_24hr).apply(
    lambda x: x.abs().max(), 
    raw=True
)
```

**使用場景**:
- 反向案例過濾: `< 4%` (確保近期無大幅波動)
- 正向案例過濾: `< 8%` (排除連續暴漲)

**注意**: `return` = 當根bar的漲跌幅 = `(close - open) / open`

---

### 參數2: past_48hr_price_range
**目的**: 檢測中期價格振幅  
**計算邏輯**: 過去48hr內的**最高價與最低價差距**，標準化為百分比

**公式**:
```python
past_48hr_price_range = (
    df['high'].rolling(periods_48hr).max() - 
    df['low'].rolling(periods_48hr).min()
) / df['close'] * 100
```

**使用場景**:
- 反向案例過濾: `< 6%` (中期穩定)
- 正向案例過濾: `< 15%` (排除極端波動)

---

### 參數3: past_72hr_avg_bar_volatility
**目的**: 檢測長期整體波動水平  
**計算邏輯**: 過去72hr內，每根bar漲跌幅的**絕對值平均**

**公式**:
```python
past_72hr_avg_bar_volatility = df['return'].abs().rolling(periods_72hr).mean()
```

**使用場景**:
- 反向案例過濾: `< 2%` (整體平穩)
- 正向案例過濾: `2-5%` (適度活躍，排除死水)

---

### 參數4: past_48hr_directional_movement
**目的**: 區分「單向趨勢」vs「來回震盪」  
**計算邏輯**: 48hr內**累積漲跌幅絕對值** / **各bar漲跌幅絕對值總和**

**公式**:
```python
sum_directional = df['return'].rolling(periods_48hr).sum().abs()
sum_volatility = df['return'].abs().rolling(periods_48hr).sum()
past_48hr_directional_movement = sum_directional / sum_volatility
```

**數值含義**:
- 接近 1.0: 單向移動（趨勢）
- 接近 0.0: 來回震盪（盤整）

**使用場景**:
- 反向案例過濾: `< 0.3` (確認是震盪，非趨勢中暫停)

---

### 參數5: past_24hr_volume_stability
**目的**: 檢測成交量是否穩定（配合價格穩定）  
**計算邏輯**: 過去24hr成交量的**變異係數 (CV)**

**公式**:
```python
volume_mean = df['volume'].rolling(periods_24hr).mean()
volume_std = df['volume'].rolling(periods_24hr).std()
past_24hr_volume_stability = volume_std / volume_mean
```

**數值含義**:
- < 0.5: 成交量穩定
- > 1.0: 成交量異常波動

**使用場景**:
- 反向案例過濾: `< 0.7` (成交量穩定)

## 四、性能優化要求（關鍵）

### ✅ 必須使用的高效方法
1. **pandas向量化**: 使用 `.rolling().apply()` 批量計算
2. **raw=True參數**: `rolling().apply(func, raw=True)` 傳遞numpy數組而非Series
3. **避免循環**: 絕對不要用 `for i in range(len(df))`
4. **一次性計算**: 5個參數一次遍歷完成，不要分5次

### ❌ 禁止使用的低效方法
```python
# 錯誤示範（會非常慢）
for i in range(len(df)):
    past_data = df.iloc[i-periods_24hr:i]
    df.loc[i, 'param'] = past_data['return'].abs().max()
```

### ✅ 正確的向量化實作模板
```python
def calculate_past_features_vectorized(df, periods_24hr, periods_48hr, periods_72hr):
    """一次性計算所有5個歷史特徵參數（向量化）"""
    
    # 確保return列存在
    if 'return' not in df.columns:
        df['return'] = (df['close'] - df['open']) / df['open'] * 100
    
    # 1. past_24hr_max_single_move
    df['past_24hr_max_single_move'] = df['return'].abs().rolling(periods_24hr).max()
    
    # 2. past_48hr_price_range  
    high_48hr = df['high'].rolling(periods_48hr).max()
    low_48hr = df['low'].rolling(periods_48hr).min()
    df['past_48hr_price_range'] = (high_48hr - low_48hr) / df['close'] * 100
    
    # 3. past_72hr_avg_bar_volatility
    df['past_72hr_avg_bar_volatility'] = df['return'].abs().rolling(periods_72hr).mean()
    
    # 4. past_48hr_directional_movement
    sum_directional = df['return'].rolling(periods_48hr).sum().abs()
    sum_volatility = df['return'].abs().rolling(periods_48hr).sum()
    df['past_48hr_directional_movement'] = sum_directional / (sum_volatility + 1e-10)
    
    # 5. past_24hr_volume_stability
    volume_mean = df['volume'].rolling(periods_24hr).mean()
    volume_std = df['volume'].rolling(periods_24hr).std()
    df['past_24hr_volume_stability'] = volume_std / (volume_mean + 1e-10)
    
    return df
```

**性能目標**: 10萬行數據 < 2秒

3. 日誌記錄新參數統計:
   ```python

       'past_24hr_max_single_move',

       'past_24hr_volume_stability'

       if param in df.columns:
   ```

## 九、注意事項

### 1. NaN值處理
- 前N根bar會自然產生NaN（因為沒有足夠的歷史數據）
- 這是**正常且預期的**行為
- 在篩選階段會自動排除這些行

### 2. 除零保護
```python
# 必須加上小值避免除零
df['param'] = numerator / (denominator + 1e-10)
```

### 3. 不同timeframe的一致性
- 確保使用 `self._get_timeframe_periods(timeframe)` 獲取正確的periods
- 不要硬編碼bar數量

### 4. 與現有30參數的關係
- 新5參數是**補充**，不取代現有參數
- 在案例搜尋時作為**額外過濾條件**
- 優先計算基礎參數（price_change等），再計算歷史特徵
