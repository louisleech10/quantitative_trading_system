## 1. 手動驗證指南（圖形界面操作）

這是一份**完全圖形化**的操作指南，即使完全不懂程式碼，也能獨立完成驗證。

### 1.1 環境準備（首次使用必做）

#### 步驟 1: 啟動後端服務器

1. **打開終端（Terminal）**
   - Mac: 按 `Cmd + Space`，輸入 "Terminal"，按 Enter
   - Windows: 按 `Win + R`，輸入 "cmd"，按 Enter

2. **進入專案目錄並啟動後端**
   ```bash
   # 複製以下整段命令，貼到終端，按 Enter
   cd /Users/louis/Desktop/quantitative_trading_system
   python -m uvicorn api.main:app --reload --port 8000
   ```

3. **驗證後端啟動成功**
   - ✅ **成功標誌**: 看到以下訊息
     ```
     INFO:     Uvicorn running on http://127.0.0.1:8000
     INFO:     Application startup complete.
     ```
   - ❌ **如果失敗**:
     - 檢查錯誤訊息，可能是 port 8000 被佔用
     - 解決方式: 改用 `--port 8001`

4. **保持此終端窗口開啟**（不要關閉）

---

#### 步驟 2: 啟動前端開發服務器

1. **打開新的終端視窗**
   - Mac: 按 `Cmd + N`（在 Terminal 中）
   - Windows: 再次打開 cmd

2. **進入前端目錄並啟動**
   ```bash
   # 複製以下命令，貼到新終端，按 Enter
   cd /Users/louis/Desktop/quantitative_trading_system/frontend
   npm run dev
   ```

3. **驗證前端啟動成功**
   - ✅ **成功標誌**: 看到以下訊息
     ```
     ▲ Next.js 14.x.x
     - Local:        http://localhost:3000
     - Network:      http://192.168.x.x:3000

     ✓ Ready in 2.5s
     ```
   - ❌ **如果失敗**:
     - 錯誤訊息包含 "npm: command not found"
       - 解決: 需要先安裝 Node.js
     - 錯誤訊息包含 "Cannot find module"
       - 解決: 執行 `npm install`，然後重試

4. **保持此終端窗口開啟**（不要關閉）

---

#### 步驟 3: 打開瀏覽器

1. **推薦瀏覽器**: Chrome 或 Edge（避免使用 Safari）

2. **前往網址**: `http://localhost:3000`

3. **驗證頁面載入**
   - ✅ 應該看到系統首頁
   - ❌ 如果看到「無法連接」，檢查前端是否啟動成功

#### 測試案例 1: 創建優化任務 ⭐⭐⭐（核心功能）

**目標**: 驗證能夠成功創建並啟動 Optuna 優化任務

**步驟**:

1. **導航到策略測試頁面**
   - 點擊左側選單的「Strategy Test」
   - 或直接在瀏覽器輸入: `http://localhost:3000/strategy-test`

2. **選擇正例案例（Positive Cases）**
   - 找到標題為「Positive Cases」的區域
   - 勾選至少 **10 個案例**（建議 15 個）
   - ✅ **驗證點**: 右上角顯示「15 selected」

3. **選擇反例案例（Negative Cases）**
   - 找到標題為「Negative Cases」的區域
   - 勾選至少 **10 個案例**（建議 15 個）
   - ✅ **驗證點**: 右上角顯示「15 selected」

4. **配置 Optuna 優化設定**
   - 找到「Optuna 參數優化設定」折疊面板（Accordion）
   - 點擊展開
   - 切換「啟用優化」開關為 **ON**
   - 設定以下參數（測試用小規模）:
     - **Trial 次數**: `20` ← 重要！測試用小數字
     - **超時時間**: `300` 秒（5 分鐘）
     - **隨機種子**: `42` ← 可重現結果
     - **啟用剪枝**: `ON`
   - ✅ **驗證點**: 所有設定值正確顯示在輸入框中

5. **配置參數搜索空間（可選）**
   - 保持預設值即可，或自訂:
     - EMA Short: 5-15
     - EMA Mid: 20-40
     - EMA Long: 50-100
   - ✅ **驗證點**: 無警告訊息（如「short_max >= mid_min」）

6. **啟動優化**
   - 滾動到頁面底部
   - 點擊「開始優化」按鈕
   - ✅ **驗證點 1**: 按鈕變為「優化中...」且不可點擊
   - ✅ **驗證點 2**: 出現進度條（初始 0%）
   - ✅ **驗證點 3**: 顯示「預估剩餘時間」（ETA）

7. **監控進度（約 3-5 分鐘）**
   - 觀察進度條每隔 3-5 秒更新
   - 觀察「最佳值」數值逐漸改善
   - ✅ **驗證點 1**: Trial 數量遞增（1/20 → 2/20 → ... → 20/20）
   - ✅ **驗證點 2**: 進度百分比遞增（5% → 10% → ... → 100%）
   - ✅ **驗證點 3**: ETA 逐漸減少

8. **等待完成**
   - 當 Trial 達到 20/20 時
   - ✅ **驗證點 1**: 顯示「優化完成」綠色訊息
   - ✅ **驗證點 2**: 出現「查看結果」按鈕
   - ✅ **驗證點 3**: 顯示最終最佳參數

**預期結果**:
- 優化成功完成 20 次 Trial
- 無錯誤訊息
- 耗時約 3-5 分鐘

#### 測試案例 2: 查看優化結果 - 最佳結果卡片 ⭐⭐⭐

**目標**: 驗證結果頁面正確顯示最佳優化結果

**前置條件**: 完成測試案例 1

**步驟**:

1. **導航到結果頁面**
   - 方式 1: 優化完成後，點擊「查看結果」按鈕
   - 方式 2: 手動訪問 `http://localhost:3000/optimization-result/[taskId]`
     - taskId 可從完成訊息或 URL 中獲取

2. **驗證頁面載入**
   - ✅ 應該看到頁面標題: 「優化結果」
   - ✅ 應該看到麵包屑導航: 首頁 / 優化任務 / Task #xxx

3. **驗證最佳結果卡片（BestResultCard）**

   **區塊 1: 標題區**
   - ✅ 應顯示: 「最佳優化結果」
   - ✅ 應顯示: Trial 編號 Badge（如 "Trial #12"）
   - ✅ 應顯示: 總試驗次數和耗時（如 "共執行 20 次試驗，耗時 4.5m"）

   **區塊 2: 最佳目標值**
   - ✅ 應顯示: 綠色大數字（如 "0.856734"）
   - ✅ 應顯示: 優化方向 Badge（"最大化" 或 "最小化"）
   - ✅ 數值應該 > 0 且 < 10（合理範圍）

   **區塊 3: 最佳參數組合**
   - ✅ 應顯示: 參數列表（通常 4-6 個參數）
   - ✅ 每個參數應顯示:
     - 參數名（如 "ema_short"）
     - 參數值（如 "8.00"）
   - ✅ 參數應該符合約束: short < mid < long

   **區塊 4: 操作按鈕**
   - ✅ 應顯示: 「複製」按鈕
   - ✅ 應顯示: 「重新測試」按鈕（如果有 onRetest）

4. **測試複製功能**
   - 點擊「複製」按鈕
   - ✅ **驗證點 1**: 按鈕文字變為「已複製」（2 秒後恢復）
   - ✅ **驗證點 2**: 打開文字編輯器，按 Cmd+V/Ctrl+V 貼上
   - ✅ **驗證點 3**: 應該貼出 JSON 格式的參數

**預期結果**:
- 最佳結果卡片完整顯示
- 所有數值合理且格式正確
- 複製功能正常

#### 測試案例 10: 雙密度模式驗證 ⭐⭐⭐（進階功能）

**目標**: 驗證設置 `far_lookback_bars` 後的雙密度優化模式

**背景說明**:
雙密度模式是 Optuna 優化器的進階功能。當設置 `far_lookback_bars` 時，優化目標會從簡單的 `separation`（正反例密度差）切換為加權雙密度得分，同時考慮：
- **信號聚集度 (Clustering)**: 正例信號在近期窗口的聚集程度
- **正反例區分度 (Discrimination)**: `ratio_separation`（近遠比的差異）

**步驟**:

1. **導航到策略測試頁面**
   - 前往 `http://localhost:3000/strategy-test`

2. **選擇案例**
   - 選擇 15+ 正例案例
   - 選擇 15+ 反例案例

3. **配置訓練窗口（關鍵步驟）**
   - 找到「訓練窗口配置」面板
   - 設定:
     - **Near Lookback Bars**: `100`（近期窗口）
     - **Far Lookback Bars**: `500`（遠期窗口）← 這會啟用雙密度模式
   - ✅ **驗證點**: 應顯示「雙密度模式已啟用」提示

4. **配置 Optuna 設定**
   - Trial 次數: `20`
   - 其他保持預設

5. **啟動優化**
   - 點擊「開始優化」
   - ✅ **驗證點 1**: 後端日誌顯示「雙密度模式啟用」
   - ✅ **驗證點 2**: 進度更新正常

6. **查看結果**
   - 優化完成後，查看結果頁面
   - ✅ **驗證點 1**: 最佳結果顯示 `ratio_separation` 指標
   - ✅ **驗證點 2**: 顯示 `near_far_ratio` 相關參數

**預期結果**:
- 雙密度模式正確啟用
- 優化目標為加權雙密度得分
- 結果頁面顯示相關指標

```bash
lsof -i :8000

```

```bash
# 安裝依賴

```

```bash
node --version

```

**解決方案 2**: 依賴未安裝
```bash
# 安裝依賴
cd frontend
npm install
```

**解決方案 3**: Port 3000 被佔用
```bash
# 檢查 port 3000
lsof -i :3000

# 將 "dev": "next dev" 改為 "dev": "next dev -p 3001"
```

### 5.3 WebSocket 實時推送

| 端點 | 說明 |
|------|------|
| `ws://localhost:8000/ws/optimization/{task_id}` | 優化進度實時推送 |

- `optimization_finished` - 優化完成
- `ping` - 心跳包 (每 30 秒)
