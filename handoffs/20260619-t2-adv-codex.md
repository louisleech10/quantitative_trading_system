Verdict: 需修補後派工。

Findings:
1. BLOCKING High — fail-open 測試放錯層。SPEC/TODO 只要求 cb try/except，但 FeatureFactory._report_progress 直接呼叫 callback；若 callback 例外會穿回 layer 執行並讓子進程 future 失敗。需測「callback raises」仍生成完成，最好 _report_progress 自身 fail-open 或 callback wrapper 覆蓋所有例外。
2. MAJOR High — WS contract 前提錯。SPEC 驗證寫 per_symbol[].current_stage，但現有 batch status/WS 是 current_symbol/current_timeframe/results/errors，且 feature_factory_ws 白名單重包 payload。需定義實際 schema，並同步 Pydantic BatchTaskStatusResponse、WS mapper、TS type、Zustand normalize。
3. MAJOR High — 不洗版假設未驗證。單 TF 約 L1-L6 + L6.5 邊界可低頻，但 multi-TF generator 另有 multi_tf/persist/complete stages、CGSA parallel TF workers；1 symbol 16-30 行不是無條件事實。需限定 scope 或分單 TF/multi-TF 上限與測試。
4. MAJOR Medium — 父 tail jsonl 與 ProcessPool 生命週期設計不足。TODO 未指定 layer_metrics_path 設定/還原位置、checkpoint 記錄、讀取時機、半行解析策略、檔案增長成本。父現有 notify 只在提交/完成 item 時觸發；若不額外輪詢，長 layer 中 WS 不會更新。
5. MAJOR High — 「byte 不變足夠」只能證明輸出檔，不能證明觀測性完全無副作用。callback 可能改變 timing、cache-hit path 可能無事件、force_regenerate/真實 batch path 未覆蓋。需加 cache-hit 無檔/有檔預期、callback 例外、寫檔失敗、jsonl 壞行、真實 1-2 symbol batch 的端到端驗證。
6. MINOR Medium — RSS「遞增」斷言不可靠。實際 RSS 會因 GC/memmap/釋放下降；應改成存在、非負、合理型別/範圍，不要求單調。

被當成事實的未驗證假設:
- 「每個 layer 邊界觸發」漏掉 multi-TF 自有 progress stages 與 cache-hit 無 layer 事件。
- 「跟現有 notify 節奏即可低頻讀」無法提供 layer 進行中更新，因現有 batch notify 主要在 item submit/finish。
- 「只新增欄位」低估了 API response model、WS mapper、frontend store normalization 的白名單/型別變更。

Suggested repair:
- 先補 SPEC schema：建議 per_symbol_status: [{symbol,timeframe,status,current_stage,stage_progress,rss_mb,updated_at}] 或明確只支援 current running symbol。
- 明確 layer_metrics_path env/checkpoint/restore 生命週期，tail parser 跳過 JSONDecodeError 半行，限制讀最後 N KB 或 offset cache。
- 驗證命令新增 callback raises/failing append、bad jsonl、old task no file、WS mapper、HTTP response model、Zustand normalization、multi-TF 或明確排除 multi-TF。
