**總結判斷**

階段五目前不是一個完整家族，而是三塊分散能力：IC Stage6 去冗餘是主流程 ✅；centrality/exposure/orthogonalization 是 deep analysis 🔌；XGB/LGBM/SHAP 是 pattern 獨立頁 ✅ 但和 IC ⛓️‍💥；多因子組合 IC 基本 ❌。

最危險的大尺度點是 `RedundancyFilter`：主流程沒有後端硬 cap，完整 corr / clustering / VIF 都可能在 430K×20K 直接爆。現有防線主要靠前端預設 `max_features=30`、輸入 max=500、cross-sectional >50 擋，但 API 層 `FeatureFilterConfig.max_features` 是 optional，不能當安全邊界。

**互審重點建議**

1. 要求另一輪專門驗證：`PerformanceConfig.max_features_for_correlation=200` 是否任何地方真的限制 Stage6。我的讀碼結論是沒有。
2. 要求另一輪專門驗證：deep analysis 若 API 直接不傳 `selected_features`，是否可能落到全部 `_filtered_features_df`。
3. 要求另一輪把「多因子組合」和 `optimization/model_config/sample_weight` 再交叉查一次；我的結論是鄰近能力有，但不是 IC weighted composite factor。
