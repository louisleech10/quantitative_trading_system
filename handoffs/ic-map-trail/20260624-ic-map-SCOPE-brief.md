# 任務：定義「IC-Analysis 分析類型全覆蓋地圖」的範疇與內容（SCOPE 定義輪）

READ-ONLY 研究諮詢。**這一輪只定義「地圖要涵蓋哪些分析類型 + 每條目要寫什麼內容」**（等於先敲定目錄/schema），**還不要寫完整地圖內容**。產出你自己的獨立提案。

## 使用者處境（定範疇的依據）
- 在做**泛用型**因子/訊號研究平台（不是單一策略）。
- **沒有量化背景**，只知道「連續 IC」「事件 IC」兩個詞，不知道還缺哪些分析類型，也不懂各類型差異。所以地圖要兼具**教學性**（白話）與**完整性**（補他不知道的）。
- **主戰場**：100 symbol、各有自訂事件時間點、分正/反案例，找「正向事件**發生前**的共通 pattern」= case-control 事件研究。現況此路徑半成品（IC event 模式只是條件查詢，不吃顯式事件清單+正反標籤+事件前窗）。
- **尺度**：單 symbol 可達 430K 欄 × 20K 列；跨標的數十～上百 symbol。
- 已知現況缺口：無 pooled/panel 時序 IC（普適性）模式；主路徑無 train/test 切分（洩漏風險）；grouped/decay 會崩潰。

## 你要交付（本輪 = SCOPE，不是完整地圖）
1. **分析類型清單**：列出一個泛用因子/訊號研究平台**該涵蓋的所有分析類型**，分門別類。**務必補上使用者不知道、但業界標準該有的類型**（這是重點——他不知道自己缺什麼）。每類一句話點出「它回答什麼問題」。涵蓋至少但不限於：時序 IC（含多 symbol 普適性/一致性）、橫截面 IC、事件/case-control 研究、分位/單調性、IC 衰減/半衰期、分組/狀態(regime)條件 IC、多空因子報酬、換手/成本、IC 顯著性/FDR/多重比較、共線性/正交化/因子擁擠、因子中心性/暴露、品質診斷、walk-forward/OOS/purged CV、多因子組合、非線性/ML 特徵重要性、穩定性…等。**你認為還該有什麼也提出。**
2. **每條目的內容 schema**：地圖裡每一種分析類型要寫哪些欄位（例：回答什麼問題/業界標準做法/平台現況實作/做對沒·漏洞/430K尺度怎麼做對又快/PIT與洩漏注意/對應現有模組）。提出你認為最有用的欄位集。
3. **地圖的組織方式**：怎麼分群/排序最好讓非量化使用者看懂（例：按「研究問題」分群？按 pipeline 階段？按 input 資料形狀？）。
4. **明確標出**：哪些類型是「使用者主戰場(事件 case-control)必須優先補強」、哪些是「現有但壞掉」、哪些是「完全缺」。

輸出格式：標題「SCOPE 提案 — <你的家族>」，分上述 1-4 節。精簡、條列、可被另三家詰問。**不要寫完整地圖,只定範疇。**
