以下是針對『量化業界完整性 + 邏輯一致性』的純量化審查結果（不涉入程式碼現況判定）：

### 1. 各型的『業界標準做法』、『資料形狀』、『PIT防禦』與『大尺度對策』審查
整體量化邏輯與業界防禦觀念非常紮實，細節精確度高。
*   **Type 1 (單標的時序 IC)**：邏輯正確。**補充微調**：關於「主路徑無 train/test→過擬合洩漏」，純算 IC 作為描述性統計時不需切分；但若依據此 IC 進行「特徵篩選 (Feature Selection) 或排序」，則使用全樣本 IC 絕對會造成嚴重的前視偏誤 (Look-ahead bias)，必須嚴格區分 IS/OOS。
*   **Type 3 (Pooled IC)**：防禦點提到「pool 標準化分位只能 train window」非常精確，這是實務上極容易踩坑的未來數據洩漏點（例如用全時間序列的 Mean/Std 偷看未來來做 Z-score）。
*   **Type 5 (橫截面 IC)**：描述完全符合業界多因子模型的 Alpha 核心檢驗標準。
*   **Type 2 & 4**：指標定義與防禦皆符合實務（Rolling 抓穩定性，Consistency 抓廣度）。大尺度對策使用 Welford 與串流也是系統工程上的正確解。
*   **【程式碼現況註記】**：第 1 至 6 型的「程式碼判定與現況（如 ✅、❌、🔌、行號等）」，**一律標為『未驗證(非我職責)』**。

### 2. 階段一『訊號有效性初探』有無遺漏？
**有。在量化業界，要證明一個訊號「初步有效」，光看 IC (相關性) 是不夠的。強烈建議補上以下兩種核心分析：**
*   **分位數分析 / 分層回測 (Quantile Analysis / Portfolio Sorts)**：
    *   **為何該有**：IC 只能捕捉線性或整體的秩相關。許多阿爾法訊號是「非線性」的（例如：極端高值才有效，或是多頭有效但空頭無效）。必須將標的依因子值分組（如五分位或十分位），檢驗各組 Forward Return 是否具備單調性 (Monotonicity)，以及 Top-Bottom Spread 的顯著性。這通常是與 IC 並列的必做項目。
*   **因子自相關性與衰減分析 (Factor Autocorrelation / Decay)**：
    *   **為何該有**：如果一個因子 IC 很高，但其值在相鄰兩期劇烈翻轉（自相關性趨近 0 甚至為負），這代表它需要極高的換手率，扣除手續費與滑價後通常毫無實戰價值。在「初探」階段，這是快速濾除「高頻雜訊假影 (Artifacts)」的必備防線。

### 3. Case-control (Type 6) 業界標準描述是否完整？
Claude 的描述（顯式事件清單 + 前窗對齊 + 判別指標 + 正反 matching + 事件重疊 purge + OOS）已經涵蓋了事件驅動研究的優秀骨架，但針對高達「430K 特徵」的尋找，**漏了兩個致命的量化陷阱**：
*   **多重檢定校正 (Multiple Testing Correction) [嚴重遺漏]**：
    *   在 430K 個欄位中盲撈判別指標 (AUC/t-stat)，必然會產生海量的偽陽性 (False Positives)。描述中必須加入對 p-value 的懲罰或校正機制，例如 FDR (False Discovery Rate控制)、Bonferroni 校正、或是 Deflated Sharpe Ratio 的概念，否則找出來的「共通先兆」大概率只是隨機雜訊。
*   **波動率 / 市場基準調整 (Volatility / Regime Adjustment)**：
    *   正反例 matching 時，除了特徵對齊，計算判別指標前的數據通常需要做波動率縮放 (Volatility-scaled) 或扣除大盤表現 (Abnormal Return)。否則找出的特徵可能只是反映當時全市場的波動率放大，而非該事件特有的預測訊號。

### 4. 優先級排序是否合理？
**合理，邏輯非常清晰。**
在一個「ML-first」且面臨「超大特徵庫（如 430K）」的系統語境下：
*   **Type 6 (Case-control) 🎯 絕對優先**：直接對標特定事件或異常報酬進行精準打擊，是機器學習最能發揮非線性優勢的戰場，排第一完全正確。
*   **Type 5 (橫截面)、Type 4 (一致性)、Type 3 (Pooled)**：檢驗多標的普適性 Alpha，符合正規量化路徑，排高中段合理。
*   **Type 1 (單標的 TS) 與 Type 2 (Rolling)**：單一標的時序雜訊最大，且 Rolling 運算極度耗費資源，在確認因子有橫截面或池化價值前就去硬算 Rolling 容易浪費算力，排在最後是明智的資源分配。
