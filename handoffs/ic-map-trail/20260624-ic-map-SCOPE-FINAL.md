## 每條目的內容 Schema（9 欄，四家合 + 全棧狀態）
1. **🔍 回答的核心問題**（白話）
2. **📐 業界標準做法**（Rank/Pearson IC 選擇等）
3. **🗂 資料形狀與輸入**（Panel / Pooled / 事件清單+標籤 / 單標的時序）← Gemini 補
4. **📊 平台現況 + 實際怎麼實作**（讀碼查證：逐symbol還pool、event吃不吃顯式清單、有沒有切train/test）
5. **🧩 全棧實作狀態**（使用者補；逐項三欄查證，揪「貌似有實則斷」）：
   - **後端 code**：有 / 空殼 / 無
   - **前端 UI·UX**：有 / 無
   - **連結(wiring)**：前端送的參數後端有真的吃嗎 / 後端結果前端有顯示嗎
   - → 綜合判定為下列其一：
     - ✅ **全棧連通**（後端+前端+wiring+正確）
     - 🔌 **後端有·前端缺**（有 code 但沒 UI，使用者用不到）
     - 🎨 **前端有·後端缺/空殼**（UI 點得到但後端沒實作 → 假功能）
     - ⛓️‍💥 **兩端有·沒連結**（最危險：前端送、後端忽略 / 後端算、前端不顯示 → **靜默失效**，如今天的幽靈 feature_filter）
     - ⚠️ **有但壞掉**（會 crash / 算錯）
     - ❌ **完全缺**
6. **🛡️ PIT 與洩漏防禦**（該分析最易踩的未來函數地雷）
7. **⚡ 430K×20K×百symbol 尺度對策**（分塊/串流/避免跨symbol groupby 爆炸）
8. **🔧 做對沒 / 漏洞**
9. **🏷️ 優先級**（🎯主戰場必做 / 高 / 中 / 低）

## 組織方式：按「訊號研究生命週期」漸進提問（Gemini 提，非量化最易懂）
照漏斗順序往下檢查，每階段回答一句白話問題。

### 階段一：訊號有效性初探 —— 這訊號真能預測未來嗎？
| 類型 | 核心問題 | 狀態 |
|---|---|---|
| 單標的時序 IC | 單一標的,因子今天值能預測它自己未來嗎 | ✅ |
| Rolling IC / IC 時間序列 | 預測力穩定還是只在某時段 | ✅ |
| **Pooled/Panel 時序 IC（普適性）** | 綜合所有時間+標的,總體預測力如何 | ❌ 高 |
| symbol 一致性/普適性 | 每symbol各算IC,看正負/勝率/離群 | 🔶 |
| 橫截面 IC | 同一時間點,能否區分多標的贏家輸家 | ✅ |
| **🎯 事件/case-control 研究** | 正向事件**發生前**有無共通先兆 | **🎯 完全缺·絕對優先** |

### 階段二：品質、動態與細節 —— 撐多久?線性嗎?挑對環境嗎?
| 類型 | 核心問題 | 狀態 |
|---|---|---|
| 分位/單調性 | 特徵越極端報酬越極端,還是中間最好(非線性) | ⚠️ 部分壞 |
| IC 衰減/半衰期 | 訊號發生後撐幾根bar才消失 | ⚠️ 崩潰 |
| 分組/狀態(regime) 條件 IC | 只在多頭/高波動才有效嗎 | ⚠️ 崩潰 |
| 穩定性/一致性 (Win Rate, ICIR) | 靠某幾天極端拉高,還是每天穩定輸出 | 🔶 |

### 階段三：統計嚴謹度與防偽 —— 是運氣/過擬合/偷看未來嗎?
| 類型 | 核心問題 | 狀態 |
|---|---|---|
| **IC 顯著性 (t-stat/bootstrap CI)** | 這IC是運氣還是統計顯著 | 🔶 |
| **多重比較 FDR/Bonferroni** | 測43萬,多少高IC只是運氣好 | ❌ 高(非量化常忽略) |
| block bootstrap/clustered SE | 處理時序自相關、同symbol群聚 | ❌ |
| **train/test split** | 嚴格不偷看未來切分後還有效嗎 | **❌ 主路徑缺·最高** |
| walk-forward / rolling OOS | 滾動訓練→驗證的泛化 | ✅ 模組 |
| purged / combinatorial purged CV | 事件重疊時CV標籤洩漏 | ✅ 模組 |
| **極端值影響診斷** | 拿掉最極端1%,IC是否歸零(防髒資料) | ❌ ← Gemini 補 |

### 階段四：實戰寫實度 —— 扣成本還賺嗎?
| 類型 | 核心問題 | 狀態 |
|---|---|---|
| 多空組合報酬/價差 | 買前10%賣後10%,報酬曲線長怎樣 | ✅ |
| 換手率/交易成本/net IC | 訊號變太快,賺的夠付手續費嗎 | ✅ |
| 流動性/容量/slippage | 能容納多少資金不滑價 | ❌ |

### 階段五：多因子與系統觀 —— 比起現有特徵,有獨特新資訊嗎?
| 類型 | 核心問題 | 狀態 |
|---|---|---|
| 相關/clustering/VIF | 新特徵是否跟現有高度重複 | ✅ |
| 正交化/neutralized IC | 扣掉已知因子後還有新資訊嗎 | ✅ 預設關 |
| 擁擠/centrality | 哪些是擁擠核心,哪些獨立 | ✅ |
| 非線性 ML 特徵重要性 (SHAP) | XGBoost裡這特徵貢獻多大 | ❌(有引擎沒接) |
| 因子暴露/歸因 | 賺錢是只在賭大盤(Beta)還是真Alpha | ✅ 預設關 |
| 多因子組合 (IC加權/組合IC) | 多個弱因子合成強訊號怎麼配權 | 🔶 待確認 |

### 橫切（貫穿所有階段，非單一類型）
- **資料品質前置**：NaN/inf/常數偵測 ✅、前處理(winsor/zscore) PIT 審計 🔶
- **訊號密度 (signal density)**：事件前後 pattern 在時間上多密 ✅(另一模組)

## 優先級總覽（四家共識）
1. **🎯 絕對優先（你主戰場）**：事件/case-control（顯式事件清單[時間,symbol,標籤] + 事件前窗 + train/test）。
2. **⚠️ 緊急修復（現有但壞掉）**：IC 衰減、分組/分位（崩潰,需修大尺度記憶體+邏輯）。
3. **🛡️ 護城河補漏（完全缺）**：Pooled 時序 IC、train/test split + purged CV、FDR 多重比較。
4. **中/低**：其餘現有需 scale 化 / 進階(ML SHAP、容量)。

## 四家交叉驗證結論
- 範疇完整性：四個不同家族獨立列舉,類型清單高度重疊、無重大遺漏 → 可信「逼近業界完整」。
- 組織法：採 Gemini 的「研究生命週期 5 階段漏斗」(對非量化最友善)。
- 待使用者最終確認：有沒有「你想做、這裡仍沒有」的分析?無的話即進「填完整地圖內容」(逐條 8 欄,含讀碼查證現況)。
