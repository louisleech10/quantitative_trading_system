## 乾跑挖出的三個缺陷

### 缺陷 1：白話檔被當成 ROADMAP 之「權威路徑」
`docs/ROADMAP.md:41` 之 `RM-TIERTOGGLE` 列，權威路徑欄逐字為 `白話說明/EVTLABEL施工進度.md`。
同型另一處：`ROADMAP.md:47` 之 `RM-GLOBALH` 權威路徑為 `白話說明/接下來要做的票.md`。
**問題**：白話說明依定義是「文件定案後另外寫給使用者的解釋」（CLAUDE.md 文件分層），
不得反向成為技術權威來源；且一旦封存，該 ROADMAP 列之權威路徑即斷。
**修法**：Phase 3 須把這兩列之權威路徑改指 `docs/` 下之技術文件；改完 `EVTLABEL施工進度.md` 才可封存。
⇒ **Phase 1 與 Phase 3 之依賴方向與 SPEC 現稿相反**（現稿寫 Phase 3 依賴 Phase 2 依賴 Phase 1）。
本條為 SPEC 缺陷，須於派審前修正。

### 缺陷 2：ROADMAP 缺 IC 健檢 epic 之列
`IC健檢施工進度.md` 自述該 epic 已收工，但 `docs/ROADMAP.md` 之 `roadmap-status` 生成區塊
**無任何 IC 健檢／ICHC 列**（實跑 `grep -n "IC健檢\|ICHC" docs/ROADMAP.md` 僅命中 `白話說明/` 路徑字串，無狀態列）。
⇒ 判準對它 fail-closed 成「留置」，**答案碰巧安全但理由是錯的**（不是因為票沒收，是因為表缺列）。
**修法**：Phase 3 補上該列後重跑判準；本票不得靠 fail-closed 掩蓋 ROADMAP 缺列。

### 缺陷 3：判準缺「常駐」這一類
導航檔（`現在做到哪`／`接下來要做什麼`／`接下來要做的票`）與我的紀錄（`治理進度日誌`／`流程摩擦記錄`）
**不對應任何單一票**，現稿判準會把它們判成 C-1-1 不成立 ⇒ 留置。答案正確但語意錯：
它們是**永不封存**，不是「這次還不能封存」。
**修法**：§C-1 改為三值（常駐／封存／留置），常駐之定義＝「不對應任何單一票之進度」，
且常駐檔須在 receipt 中明標 `permanent`，不參與後續每次求值。

## 對 SPEC 現稿之處置
上列三條皆為本 SPEC 自身缺陷，**在派審之前由主委自行修正**（非留給委員抓）。
修正後之 SPEC 版本標 v2，並於修訂沿革記明「三條由主委乾跑自檢發現」。
