# B6 Option1 read-only design note — Codex
Date: 2026-06-22 | Mode: read-only; no code changes.

## Decision summary
Option1 = date-window run loads `[start-max_warmup, end]`, computes causally within that run, then all public outputs are trimmed to `[start,end]`. It does **not** promise full-range byte parity because fracdiff/ADF/cumulative are position-dependent.

## 1. Falsifiable validation contract
Primary proof should be **edge-usability + causal/trim invariants**, not byte parity.
- T1 flag-on vs flag-off on same real symbol/TF/date window: first K rows after `start` have materially lower feature NaN ratio with flag-on; K should be tied to computed warmup sources, not a magic number.
- T2 warmup rows are never exposed: final `features_df`, `labels_df`, HDF5/CGSA raw artifact, registry `row_count`, manifest `row_index/time_range`, browse rows, batch checkpoint output all start at requested `start`.
- T3 causal self-consistency: changing/removing data before the loaded warmup start cannot affect output; changing rows after timestamp t cannot affect features at <=t.
- T4 allclose is only a supporting test for explicitly position-invariant columns. It must use column allowlist/exclusion manifest, exact NaN-mask equality, and dtype-aware tolerances. It is not the definition of warmup success.
- T5 multi-TF: aligned primary axis has no warmup timestamps; each source TF has its own sufficient pre-start source rows before alignment.

## 2. Cumulative
Use warmup-window cumulative, document values as **run-relative absolute levels**. Do not load dataset-start by default: it explodes IO and creates a different contract from Option1. Mark OBV/AD/ADOSC/VWAP-style cumulative columns as position-dependent; parity/allclose tests exclude them. Future dataset-start mode can be a separate explicit mode.

## 3. Labels end-side
End+horizon is outside B6 start-scope unless separately approved. Keep current behavior: labels use `shift(-horizon)` inside the requested output window, so final horizon rows remain NaN. Document it clearly. Do not silently extend end; that changes data access, output semantics, and possibly cache/config hash.

## 4. max_warmup source checklist
Include max of:
- L1 indicator warmup from `warmup_table.yaml` for indicator periods; CDL pattern default bars; cumulative special cases treated as position-dependent, not fully solvable by finite warmup.
- L2 derived operators: configured momentum/worldquant/ts windows/lags.
- L3 rolling aggregation: max configured `rolling_aggregation.windows` for enabled aggs.
- L4 lag features: max generated lag from `sequence_length`, `max_lag_ratio`, `lag_strategy`, `custom_lags`.
- L6/meta features: any explicit rolling windows used by meta/cycle/entropy/tail-risk/microstructure configs.
- L6.5: winsor window, rank window, max adaptive-zscore windows, calibration_bars=max(adf sample, fracdiff sample, config calibration, 500), fracdiff max_lag/derived default, ADF sample/max_diff decision window.
- native-TF: compute per source TF in source rows after applying native window scaling; do not reuse primary bars blindly.
- labels: exclude from start warmup; document end horizon separately.

## 5. Minimal implementation shape
Add a single internal `requested_window`/`loaded_window` metadata object and a reusable trim mask helper. Layer0 receives expanded start; L7 and every persistence surface receives requested trim mask before writing public artifacts. Cover normal in-memory, CGSA raw stream, CGSA group persist, multi-TF serial/parallel, IC-first raw/processed, batch resume/checkpoint, and browse registration. For CGSA streaming intermediates, either trim before final public raw artifact and ensure manifests expose only trimmed rows, or explicitly mark intermediate manifests non-public/non-browseable.

## Risks / reminders
Do not call this byte parity. Do not weaken NaN/inf gates. Do not include warmup rows in IC/ML/labels. Do not let resume checkpoints produced with strict-window semantics masquerade as warmup-enabled checkpoints.
