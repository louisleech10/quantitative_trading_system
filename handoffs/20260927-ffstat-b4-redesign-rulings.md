## 二、查證事實（主委 2026-09-27 讀碼／實跑）

## 三、主委提案做法（寫入 SPEC v32 送審；使用者白話逐條審閱後才定，非已裁定）

逐欄方案（對話中主委提出、使用者未提異議但未明示同意）：

| 情境 | 提案行為 |
|---|---|
| 無起始日 | 每欄空到自己的穩定點；其後 N 個值為該欄校準窗；再其後才輸出。各欄輸出起點不同，表不切齊 |
| 有起始日 | 全欄輸出自起始日；各欄自起始日前載入預熱，並取起始日前、穩定點後之最後 N 個值校準；湊不滿者 `calibration_insufficient_history`、不平穩化、品質 partial |
| 歷史過短（如 12h） | 同上兩規則自然處理：慢欄空得較久，全段湊不滿即整欄標記；快欄照常輸出。v31 之主框架共用起點、保底 N 根主週期輸出不再需要（去留仍交委員） |
| 穩定點計算 | L1＝參數 × 倍數表係數；每經一層加工（L2–L4 之窗、L6.5 縮尾之完整窗 252）加上該層窗長−1；依各層產欄當下寫出之血緣相加 |
| 每次生成之機械檢查 | 算出之穩定點該列須為有限值，否則標出（不得靜默） |
| 倍數表 | 補量 39 指標；多時間框架取最壞值；查不到即擋下（R5） |

以下為起草時須逐項定案之技術細節（交委員會）：

- 每欄血緣（來源欄＋各層窗）之結構化記錄：現況 FF **無任何 lineage 欄位**，須於各層產欄當下寫出（不得依欄名推斷，承 FF-STAT 本旨）。
- 倍數表補量：39 指標；多時間框架（至少 5m／1h／4h／1d）取最壞值；累積型另案；「不得侷限加密貨幣」列為驗收（台美股期資料到位時補量）。
- 每次生成之機械檢查：穩定點該列須為有限值，否則標出（不得靜默）。
- 校準窗改為每欄「穩定點之後、該欄輸出開始之前」之 N 個值；有起始日時各欄往前預熱與校準、不足者 `calibration_insufficient_history`。
- v31 之主框架驗證、保底 N 根主週期輸出、`CALIBRATION_FIRST_VALID_DELAY_BARS` 之去留。
- 預熱裁切預設開啟對既有產出／快取／測試（綁 `FFACT_WARMUP_TRIM=0` 者）之影響面盤點；須改之 v31 條文至少含事實 9 所列三處，及通過條件②／Task 2.1 驗證之「`FFACT_WARMUP_TRIM=0`、`1` 各一」逐位元組全等。
- 無起始日時「預熱」無更早資料可載，只能裁掉各欄開頭；有起始日時自起始日前載入預熱；兩者之公開域計算起點與裁切規則分列。
- v31 b4 原範圍中與本裁定無衝突者保留：r6 之 IPC 清理 try 範圍修補；前端顯示（v31 字樣「特徵自 X 起（前段保留供校準）」須隨逐欄改寫）。
- 使用者前問「為何不能用那欄位第一個有數值列當500根的第一根」：逐欄設計下無起始日時，校準窗即該欄穩定點後之首 N 個值，與此問一致。
