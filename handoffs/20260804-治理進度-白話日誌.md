## 2026-08-04 深夜｜偵察輪做了什麼、發現什麼

### 一句話總結

**原本以為 `B-15` 只是「唯讀指令被誤擋，煩人而已」。實際查出來，同一段程式碼裡藏著四個問題，其中兩個是「該擋的沒擋」。**

### 查到的東西（都有實跑證據，不是推測）

**1. 票上寫的原因是錯的。**
票上說「只要指令裡出現委員的名字就會被擋」。我去讀程式碼，發現它其實已經避開這種情況了（註解裡還特別說明過）。真正的原因有兩個，而且互相獨立：

- **原因 A**：它看不懂引號。指令裡引號**內**的分號會被當成「這裡是新的一條指令」。
  例：`git commit -m "…修好了; codex 那邊已複查…"` → 被擋。
- **原因 B**（更嚴重，**今晚現場抓到**）：只要指令裡出現 `claude` 這個字，**而且**後面任何地方出現 `-p` 這兩個字元，就會被擋。
  問題是——治理檔案的資料夾就叫 `.claude/`，暫存資料夾叫 `claude-501`，而 `-p` 出現在 `rev-parse`、`--porcelain` 這種常見指令裡。
  **所以「碰治理檔案的唯讀指令」等於在擲骰子。**而且中間加一根管線符號就會過，所以它看起來時靈時不靈——我過去一直以為是環境不穩。

**2. 有兩個洞是「該擋的沒擋」（比誤擋嚴重得多）。**

- 用完整路徑呼叫委員工具（例：`/opt/homebrew/bin/codex …`）**完全不會被擋**。
  而系統自己內部用的就是完整路徑——也就是說**真正的派工形態不在守備範圍內**。
- 直接執行派工腳本 `bash scripts/cx_run.sh …` **也不需要任何許可證**。
  我查了，那支腳本和它的角色檢查裡，「token」這個字出現 **0 次**。

**3. 一個更根本的問題：被擋下來的指令，系統完全沒有留下紀錄。**
擋下來的原因只記「許可證過期」或「有欠帳」兩種，**指令本身一個字都沒存**。
另一份會記指令的日誌，因為執行順序排在檢查之後，被擋時根本不會執行。

這代表：**誤擋率是憑印象講的，而且改完之後無法驗證有沒有改對。**
所以 `B-15` 要拆成兩段——先讓系統記下被擋的指令，才有辦法談改判準。

### 四家委員的結論一致

我自己寫一份、codex／grok／composer 各寫一份，四份獨立產出。四家在這四點上完全一致：

1. 票上的原因不能沿用
2. 其中一個修法方案（只認「有沒有呼叫官方腳本」）**單獨用會變成大漏洞**——手動打的派工指令全部漏網
3. `B-24` 說「不另外做檢查程式，只寫進規定裡」**不符合你定死的「工具必須自帶強制機制」**
4. `B-14` 想用「格式檢查過了就當成功」**不夠**——一份被截斷但恰好最後一段格式完整的報告會被誤判成功

有一個真實分歧：`B-14` 的逾時該設多久，codex 說 20 分鐘、grok 說 60 分鐘。
查下去發現**兩家量的根本是不同的東西**（一個量「報告寫完到收工」、一個量「開始到最後一次寫入」），數字差一個數量級。收斂時會先定義清楚要量什麼。

### 收斂時抓到一件事：票上寫的第三個誤擋，機制終於找到了

原本三家委員加我都「重現不出來」。結果我在查 push 結果時，**唯讀指令當場被擋**，才抓到真正的觸發條件：

> 指令裡出現 `claude` 這個字（治理資料夾 `.claude/` 和暫存區 `claude-501` 都算），
> 而且後面任何地方出現 `-p` 這兩個字元（`rev-parse`、`--porcelain`、`-print` 都算），
> 中間沒有管線符號 → 就被當成「派工」擋下。

重現不出來的原因是：大家重建指令時，不是漏了 `claude` 就是漏了 `-p`。
**這條順帶也是個漏洞**——中間加管線就會被放行，所以真正該擋的 `某某 | claude -p "…"` 反而不擋。

「修掉引號誤判」的作法（把引號內的內容忽略掉）會直接打開另一個洞：

### 先講最重要的：憲法裡那條「600 秒硬性 timeout」不成立

`CLAUDE.md` 記載權限分類器掛住時「精準落在 ~603 秒 → 確認是 600 秒硬性 timeout」。

同一晚還有一次 **603.89 秒**（那次是我違規用 `python3 -c`，屬憲法已警告的情況）。

唯一可能是它**不在 allow 清單裡**。

⚠️ **建議**：`git reset`（以及其他還沒進 allow 清單的 git 子命令）該加進 `permissions.allow`。
