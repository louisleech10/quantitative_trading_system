# 20260622 B7 L6.5 raw-sink parallel adversarial review (Codex)
Verdict: 需修補後派工。核心方案可行,但 SPEC/TODO 目前不足以保證 byte/parity、RSS、單 writer 與 ThreadPool 有效性。

## Findings
1. [BLOCKING][High] 「byte-parity」定義不成立。證據: SPEC §C/§V 寫 byte 一致但驗收是 `allclose≤1e-6+NaN mask`; raw path還有 `np.asarray(data,dtype=float32)`(feature_preprocessor.py:421-430)、L7 sanitize/dead-drop/parquet/manifest side effects(feature_storage.py:876-1024)。失敗: 值近似通過但 raw parquet/manifest/schema_hash/欄序 bytes 可漂移。修法: 改稱 value+NaN-mask parity,或新增 exact array bytes/hash+manifest ordering/file-size gate。
2. [BLOCKING][High] Task2 未明確禁止 worker 呼叫 sink/registry mutation。證據: 現 `_maybe_run_native_l65_to_sink` 直接 `sink(...)`(feature_preprocessor.py:878-886),append mode 查 `registry._groups` 產生 new id(:869-874)。失敗: 實作者若把此函式丟 ThreadPool,會破父單 writer、cleanup_source、group_manifest/nan_accumulators。修法: 先抽 pure compute helper,worker 只回傳 outputs+metadata;父按 group_plan 單線程決定 group_id/sink/cleanup。
3. [BLOCKING][High] RSS gate 公式低估 peak/queue。證據: SPEC working_peak 只列 native*3+aligned+idx_map;實作會同時持有 native_df/processed_df/orig_aligned/new_aligned(outputs)(feature_preprocessor.py:825-876),sink 會建 Arrow arrays/Table/parquet staging(feature_storage.py:956-1001),有序 sink 會暫存 out-of-order completed results。失敗: 8GB/16GB 下 completed queue + sink temps 超 budget。修法: per-task estimate 加 processed/output bytes+sink temp allowance;追蹤 result_queue_bytes;drain ready groups before new submit;無歷史 p95 時用保守 estimate 或 serial fail-closed。
4. [MAJOR][High] `p95_task_peak` 來源未定義。證據: SPEC/TODO worker formula 用 `floor(rss_budget/p95_task_peak)`,但首次 run/新 config/新 TF 無歷史。失敗: 實作可能用 0/None/舊 profile,導致過度並行或除零。修法: 定義 bootstrap: `p95=max(static_est_peak, measured_completed_peak_p95)`;未完成首批前 cap=1-2 或 serial。
5. [MAJOR][High] 窄/寬 gate 會誤排或漏排 slow path。證據: SPEC 寫「非 slow-path(fracdiff/ADF/gaussian-non-all)」;現 `_group_requires_slow_transform` 對 ADF/FracDiff 是 layer/column routing,L3 可 fast(feature_preprocessor.py:1184-1223)。失敗: 若按全域 do_adf/do_fracdiff 排除,會把目標 L3 winsor 群全序列;若只看名稱又可能漏 unknown-layer slow group。修法: eligibility 必須調用/等價於 `_group_requires_slow_transform(group,context)`,並測 L1 slow+L3 fast 混合。
6. [MAJOR][High] 「numba @njit 釋 GIL」是未驗證/不充分事實。證據: SPEC §A;實際 kernels 是 `@njit(cache=True)` 無 `nogil=True`(_numba_transforms.py:31,217),註解只說禁 `parallel=True`(:38-46)。失敗: ThreadPool 可能對 rolling_quantile_sliding 無 speedup或 GIL-bound;slow pandas/ADF 更無效。修法: SPEC 補 parallel speed microbench gate;只並行已證 release/有效的 fast kernels;slow path保持序列。
7. [MAJOR][Medium] 單 writer 與 CGSA manifest 安全只在父端成立,文件未列死鎖/鎖順序測試。證據: `_write_group` 修改 group_manifest/nan accumulators並 cleanup registry(feature_storage.py:846-1056);`release_storage` 寫 registry manifest(column_group_registry.py:1145-1188);manifest lock在 registry/FeatureStorage 各自不同(:1714-1727, feature_storage.py:1715-1770)。失敗: 若未來 worker 或 callback 進 sink/manifest,可 race或鎖順序不明。修法: TODO 加 spy: worker thread不得呼叫 sink/registry write/release;父 sink 後再 cleanup;manifest only after stream complete。
8. [MINOR][High] flag 關「今日序列」未具體到 env/測試。證據: TODO 只寫 flag 預設關;現 caller 仍傳 `FFACT_L65_WORKERS` tier值(feature_factory.py:3191-3217),raw-sink今日硬 effective=1(feature_preprocessor.py:438-449),native-tf flag `FFACT_L65_NATIVE_TF` 預設開(_native_tf_helpers.py:47-54)。修法: 指名新 flag如 `FFACT_L65_RAW_SINK_PARALLEL=0`;測 n_workers>1但flag off仍不建 ThreadPool且輸出/manifest同今日。

## 被當成事實的未驗證假設
- 「byte-parity 可由 allclose+NaN mask 保證」: assumption,非 fact。
- 「@njit 釋 GIL,ThreadPool 一定有效」: assumption,需 microbench/或 nogil 證據。
- 「p95_task_peak 可用」: assumption,首次 run 無來源。
- 「父有序 sink 足以保證安全」: conditional fact;只有 worker 不碰 sink/registry 時成立。
