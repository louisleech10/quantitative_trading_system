# B6 warmup-then-trim adversarial review — Codex

Verdict: 需修補後派工。大+(d)從嚴；目前 SPEC/TODO 有可修補缺口，但非根本重作。

Findings:
1. [BLOCKING][High] 多 TF warmup/trim 定義不足。證據: SPEC Task1.1「以 primary TF bar 為單位」+ Task2.1 改 `_layer0`; code `multi_tf_generator.py:54-60,158-165` 對 primary/secondary 都直接傳同一 start/end，`232-247` 用已切 primary_timestamps 建 idx_map。失敗: secondary TF 只載 `start-max_primary_bars` 或 strict source window，無法保證 source TF 自己 L1/L3/L6.5/native warmup；對齊前缺 source bucket 會讓 primary 起點前/起點附近 parity 假綠。修法: 明確 per-TF warmup bars/time span、primary axis 含 warmup、secondary source 起點按 source TF/對齊模式回推，所有 TF 對齊後才 trim。
2. [BLOCKING][High] 輸出 trim 落點漏 CGSA/streaming/raw/IC-first。證據: SPEC Task2.2 只說 `feature_factory.py` L7 前；code 普通 path `feature_factory.py:3409-3494`、CGSA stream `3033-3126`/`feature_storage.py:733-750,1128-1190`、multi-TF CGSA `multi_tf_generator.py:305-323,598-616` 都可直接 persist raw artifacts。失敗: 只 trim in-memory `features_df` 會讓 CGSA raw parquet/manifest row_index/time_range 仍含 warmup，或 row_count 與 [start,end] 不一致。修法: TODO 分別列 single in-memory、single CGSA stream、multi-TF CGSA serial/parallel、IC-first raw/processed 的 trim/manifest/row_index tests。
3. [MAJOR][High] 「非 fracdiff byte 一致」被過度陳述。證據: SPEC §A「唯一位置相依是 fracdiff d*」；code L6.5 winsor rolling quantile/sigma `feature_preprocessor.py:2309-2349`, rank/zscore `2414-2425,2353-2388`, FeatureValidator fallback winsor `feature_validator.py:149-155,189-214`, post-IC API rolling rank/zscore `ic_analysis_service.py:748-760`。失敗: warmup 估算若只含 pre-IC winsor/fracdiff，post-IC 或 fallback validator 的 non-fracdiff output 仍會與 full-range 不同；「byte」也不等於 allclose≤1e-6。修法: parity scope 精確限定到 generated L7 raw pre-IC non-fracdiff columns；若要含 post-IC/API transform，max_warmup 必含 rank/zscore windows 且測試真跑該路徑；文字改 allclose/value+NaN-mask，不稱 byte。
4. [MAJOR][High] max_warmup 來源仍不齊，lag/labels/ADF decision/validator fallback 未列。證據: L4 lag uses `LagProcessor` from raw/L1 at `feature_factory.py:1655-1694`; labels use future horizon `labels/label_generator.py:21-41`; ADF uses calibration/sample/max_lag `feature_preprocessor.py:3301-3344`; validator may apply rolling winsor if L6.5 winsor off. 失敗: output labels at end can be affected by `end_date` strict cut; lag depth affects early L4 parity; ADF non-fracdiff path may be an unlisted Option-A-like exception. 修法: separate feature warmup vs label lookahead/end extension vs validation mutation; explicitly include or exclude each with tests.
5. [MAJOR][Medium] PIT 可證偽條件太弱。證據: SPEC §V only asserts `warmup index<start`; labels use `shift(-horizon)` and `_layer0` currently cuts `end_date` before labels. 失敗: start-side PIT pass does not prove no end-side truncation or future label mismatch; full-range parity may fail near end. 修法: add assertions that warmup rows are excluded from IC/ML outputs, labels either excluded from parity or generated with `end+horizon` then trimmed/marked unavailable.
6. [MAJOR][High] warmup insufficient UI/API contract 空泛。證據: TODO Task3.1 says metadata through Pydantic+WS/REST but no schema fields; current `FeatureTaskStatusResponse` has no warmup warning field and batch checkpoint returns only hdf5_path/error. 失敗: backend computes warning but UI/batch/resume cannot reliably display or persist it. 修法: define exact metadata key, task status/result shape, batch checkpoint retention, TS type, and UI component/test selectors.
7. [MINOR][Medium] flag-off acceptance under-specified. 證據: SPEC says flag off golden PASS but no env var name/hash/cache behavior. 失敗: implementer may include flag/warmup metadata in config hash or registry and fragment strict cache. 修法: name flag, default, hash inclusion/exclusion, and add cache hit/golden tests.
