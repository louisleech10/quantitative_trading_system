## §B 主委自產提案（**請獨立評估或推翻，勿預設採納**）

### 提案① 共同根因判斷

現行架構是「**先轉換、再 grep**」：
`_gate_lex_preprocess` 用 awk 逐字元把引號 span 內的空白改成 US，產生一份**改寫過的完整字串**，
再對該字串做多條 `grep -Eq`。

主委認為兩個缺陷都源於這個架構：

| 缺陷 | 為何源於此架構 |
|---|---|
| **E-2 二次方** | awk 以 `tok = tok cc` 逐字元累加建構輸出 ⇒ 字串反覆重配置，O(n²) |
| **E-1 換行繞道** | 判定散落在多條 `grep`，而 `grep` **逐行處理**；自我豁免那條又非全字串錨定 ⇒ 跨行即失效 |

⇒ **沒有單一權威 tokenizer**，每個判定各自用 grep 近似，因此每加一條規則就多一個漏洞面。

### 提案② 提案：不轉換，只偵測

以**單趟 O(n) 串流狀態機**取代「轉換＋grep」，輸出結構化事實而非改寫過的字串：

```
輸入：原始 cmd
輸出（O(1) 記憶體，逐項 emit）：
  · 每個「命令位置」的起點與該位置的第一個 token
  · 每個 $()／反引號 span 的內容（供遞迴）
  · 是否出現未閉合引號／heredoc（fail-closed 訊號）
  · 命令位置總數
```

所有判定改為**查詢這個輸出**，不再各自 grep：

| 契約 | 新判法 |
|---|---|
| executor 出現在命令位置 | 命令位置 token ∈ executor 名單 |
| 引號內字面不算派工 | 狀態機在 quote 內不產生命令位置 |
| 引號內 `$()` 會執行 | 該 span 內容遞迴送入同一狀態機 |
| **自我豁免**（E-1） | **命令位置總數 == 1 且該 token 為 gate 腳本** |

⇒ E-1 自然關閉（換行會產生第 2 個命令位置 ⇒ 不符「總數 == 1」）。
⇒ E-2 自然關閉（不建輸出字串，無 O(n²) 累加）。
⇒ **長度上限可完全移除**，D-2 的誤擋摩擦也消失。
