# IC Phase 1 — 1a「訓練/測試切分」決策簡述（給使用者看）

> 白話版。不含行號/術語細節，碼證留在後續 SPEC。讀完你只需要：同意 / 改範圍。

## 一句話
現在 IC 分析「用全部資料算分數」，等於偷看了答案再評分。1a 要把資料切成「先看到的（訓練）」和「沒看到的（測試）」，所有清洗與篩選只准用訓練那段，分數只在測試那段報——這樣 IC 才能代表「未來真的會賺」而不是「事後諸葛」。

## 為什麼現在做、為什麼是大工程
- 上一刀（1-contract）已經把「防偷看的規則」寫好了，但**那些規則目前沒接到真正的主流程**——像裝了防盜門卻沒裝上門框，小偷照走。1a 就是把門框裝上。
- 它會動到 IC 的**主計算流程**（很多功能都靠它），而且碰的是**正確性/防資料洩漏**這條最敏感的線，所以照制度算「大」，要走完整的設計→雙方審查→派工→三方簽核流程。

## 1a 要做的三類事
1. **補完上一刀的三個半成品**（沒這些，防盜門規則不生效）：
   - 讓切分器知道「這次到底有哪些幣」（才能擋掉混入不該出現的幣）。
   - 讓切分器知道「資料是 1 小時還是 4 小時一根」（才能抓出中間缺漏、避免把不連續的資料當連續切）。
   - 把契約**真正接進主流程**（現在是空接、只保護沒人走的旁路）。
2. **核心正確性修復——把「偷看」堵掉**：
   - 清洗（去極端值、標準化）的「尺度」只能從訓練段學，再套到測試段；現在是拿全部資料學，等於偷看。
   - 特徵的好壞、統計顯著性，只在「沒看過的」測試段報告。
3. **守住現有行為**：沒開新功能開關時，輸出要跟現在**逐位元組一致**（不可偷偷改數字）；開了之後才走新的、正確的算法。

## 你必須知道的一個後果（重要）
一旦真的接上，**測試段報出的 IC 數字會跟現在不一樣**（通常會變低，因為不再偷看答案）。這不是 bug，是把虛高的成績擠掉水分。現有畫面/報告的數字會跟著變。
→ 我的做法（**使用者 2026-06-26 定**）：**三方數據簽核 PASS 後，新的正確算法＝預設開啟**，它是新的正常行為。開關只當「逃生口 + 對照舊數字用」（給你 diff 擠掉多少水分、緊急回退），不是預設、不是門檻。**絕不把驗過的修復藏在預設關閉的開關後**（那等於沒做還害你瞎找）。順序：實作 → 簽核 PASS → 才把預設切到新算法（不在驗證前暗著換你數字）。

## 範圍取捨（這是要你拍板的地方）
1a 牽涉的面很廣，我建議**切兩刀做**，避免一次動太多難回退：

- **1a-第一刀（建議先做）**：接好三個半成品 + 把切分/訓練段清洗接進**主流程（單幣縱向模式）**+ 守住開關關閉時數字不變。產出一條真正受保護的主路徑。
- **1a-第二刀（接著做）**：把「橫截面模式」（同一時間點跨幣排名）的防洩漏也補上——這塊上一刀明文留到 1a，邏輯跟單幣不同，獨立一刀較安全。

替代方案是**一刀全包**：範圍大、審查與回退風險高，但少一次派工往返。

## 不在 1a 範圍（後續 Phase）
FDR 接線（1b）、Net IC 量綱（1c）、因子歸因（1d）、HAC/bootstrap（1e）、空圖修復（1f）、串流承載（Phase 3）。1a 只負責「切分這件事」本身，是上述全部的前提。

## 風險與防護
- **改錯會讓所有 IC 失真** → 三方（我＋GPT-5.5＋Composer）獨立用**真實 K 線**簽「資料正確、無洩漏」才算過，不靠你驗收。
- **可能假性通過**（把門檻放寬換綠燈）→ 接回時我會 diff 既有測試斷言防假綠，並派另一方做 code review。
- **難回退** → 每步獨立可 revert；新算法用開關隔離：**初始實作先關（保 byte 不變）→ 三方簽核 PASS 後切預設開啟**，之後開關只當逃生口/對照，不永久關閉（[[feedback_no_default_off_after_validation]]）。
