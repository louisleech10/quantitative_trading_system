# 量化 ML 方法分類（參考）

> 用途：釐清 ML 方法名詞,供討論 IC→ML 橋(Phase 4)、模型選型時引用。
> 日期：2026-06-26。**結論先講:本專案是監督式 GBDT + LSTM,不是 RL。**

## 名詞地圖

```
ML（機器學習，大傘）
├─ 監督式學習（有標籤 → 預測）          ← 本專案現役
│   ├─ GBDT 梯度提升決策樹  ←── XGBoost / LightGBM / CatBoost 都是它的實作
│   ├─ 線性 / 邏輯回歸
│   └─ 神經網路（含 LSTM，本專案有）
├─ 非監督式（分群 / 降維，無標籤）
└─ 強化學習 RL（學「策略 / 動作」，序列決策）  ← 不同範式，非現役
```

## 關鍵澄清

- **GBDT ≠ 另一種方法**：GBDT(Gradient Boosted Decision Trees)是**演算法家族名**;XGBoost / LightGBM / CatBoost 是它的**具體工具庫**。文章把「GBDT」與「XGBoost/LightGBM」並列只是名詞混用——它們是同一件事。
- **監督式 vs RL 的本質差異**：
  - **監督式**(本專案)：給特徵 → 預測一個標籤(漲跌 / 報酬)。一次性預測,有正確答案。
  - **RL**：不預測標籤,而是學一個**策略**——在不同市場狀態採取什麼**動作**(買/賣/持有/部位大小),最大化**累積報酬**。序列決策。

## RL 在量化的定位（為何不急著碰）

- 真實用途：多在**下單執行最佳化、做市、動態資產配置**(連續動作場景),不是「預測訊號」。
- 風險：極度吃資料量;金融資料**非平穩 + 訊號雜訊比低** → RL 極易過擬合、難驗證真假。
- 業界生產線主流仍是**監督式 GBDT + 投資組合最佳化**,非 RL。
- 結論：RL 是更進階、更危險的另一條路,**不在現役 ROADMAP**;真要評估值不值得碰,走規劃委員會,不臨時分心。

## 對本專案的定位

- 現役 ML：**監督式**——XGBoost / LightGBM(GBDT)+ LSTM,預測訊號。
- 驗證：既有 walk-forward / CPCV(purged CV)孤島(`momentum/Analysis/model_validation/`)做防洩漏驗證。
- IC→ML 橋(Phase 4)：把 IC 篩過的存活特徵餵進 **GBDT**,屬監督式。
