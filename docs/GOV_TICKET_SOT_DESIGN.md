## 🔴 r1 打穿的自相矛盾（本版第一件要修的事）

r1 版在 `S0.1` 寫「全集由 backlog 導出、**不另存副本**」，
卻在 `S0.3` 要求 fact-key 承載每票欄位 ⇒ **兩節互斥，canonical owner 沒定**，
結果兩個檔都可手寫，「只能有一套」根本沒落實（`CODEX-R1-P0-01`）。

**本版裁定（採 codex 方向）**：

| 角色 | 承載什麼 | 可否手寫 |
|---|---|---|
| **`governance-ticket-sot`（fact-key）** | **唯一結構化 canonical record**：票號／代號／狀態／證據／覆蓋／承接／對外不得宣稱 | **只有這裡可改** |
| `handoffs/…-BACKLOG.md` | 票的**長文**（病／代價／修法方向／討論），實測 4–217 行 | 內文可改；**狀態欄一律移除**（`S0.6`） |
| `HANDOFF.md`／`GOVERNANCE_EXECUTION_ORDER.md`／白話說明 | **投影**，由 `--write` 生成 | **不可手寫**（既有偵測器已強制） |

## `S0.1` 票之全集

**定義**：票的全集 ＝ backlog 中符合 `^## B-<正整數> ` 之標題所帶識別碼。
實測 **61 張，格式無例外**。

### 🔴 typed reference：非票項不再塞進票號欄（`GROK-R1-P1-03`／`COMPOSER-R1-P0-02`）

r1 版把 `B3R`／`G-7`／`測試套件` 放進票號欄再靠白名單放行——
兩家判為**欄位型別設計缺陷**，且會使 `S1.1`「對應票須在全集內」要麼豁免白名單、
要麼自打臉 ⇒ **等於永久洞**。

**本版改為具型別的引用**，凡引用治理標的之欄位一律用 `<類型>:<識別碼>`：

| 類型 | 識別碼來源 | 例 |
|---|---|---|
| `ticket:` | `S0.1` 全集（61 張） | `ticket:B-25` |
| `batch:` | `governance-batch-status` 之批次欄 | `batch:B3R` |
| `check:` | 檢查代號（封閉具名集合） | `check:G-7`、`check:pytest-suite` |

⇒ `B3R` **不再是票**，它是批次；`enforcement` 的 `對應票` 欄改名 `對應標的` 並收 typed 值。
這同時解掉 `COMPOSER-R1-P0-01`（既有機制把 `B3R` 當票，與全集定義互斥）——
既有引用改為 `batch:B3R` 即與全集定義相容。

### 🔴 具名腳本與驗收命令（`COMPOSER-R1-P2-02`：原版屬不可測空殼）

- 列舉腳本：`scripts/ticket_universe.sh`（**待建**）
- 列舉指令：`bash scripts/ticket_universe.sh --list` → 一行一票號，`LC_ALL=C` 排序
- 驗收：`bash scripts/ticket_universe.sh --check` ⇒
  ① 重跑兩次輸出逐位元組相同 ② SoT 之票集合 **恰等於** 列舉結果 ③ 任何 typed 引用之
  `ticket:` 識別碼在全集內，否則 fail-closed
- 票號格式**寫死於該腳本**（非由資料自證，同 `_FK_RESERVED` 紀律）

### 🔴 雙端不變式（`GROK-R1-P1-04`：無此則上線日重造第二套）

`SoT 之票集合` **恰等於** `backlog 之 ^## B-<n> 集合`。
任一端單獨新增即 fail-closed——**不允許「只寫一邊」**。

## `S0.2` 唯一一套狀態語意（**五值**，`進行中` 已刪）

`進行中` 依 r1 三家一致刪除（`GROK-R1-P2-02`／`COMPOSER-R1-P1-02`／`CODEX-R1-P1-03`）：
無法從 artifact 機判、與 `部分完成`／`狀態未確認` 語意重疊、
且與 `governance-sot-plan` 的「步驟進度」撞名 ⇒ 必成人工髒欄。

| 值 | 判定條件（**全部機械可驗**） |
|---|---|
| `未開工` | 無 artifact，**且**證據範圍內確認無對應產出 |
| `部分完成` | 有 artifact，**但**三條件未齊 |
| `已完成` | 🔴 `artifact` ∧ `無阻塞殘留` ∧ `產出端覆蓋已登記` **三條齊備** |
| `已作廢` | 有裁決記錄；票列保留不刪（可稽核沿革） |
| `狀態未確認` | 證據不足以判定。🔴 **預設值，不得用猜的填其他值** |

🔴 `CODEX-R1-P1-03` 另指出實作面：現行 `_schema.status_enum` 由**四個** status key 共用
⇒ 本五值須有 **ticket-key 專屬 scope**，不得直接塞進共用列舉。

### 舊值映射（`收案` 之自動映射已移除）

| 舊 | 新 | 說明 |
|---|---|---|
| `PARTIAL` | `部分完成` | 自動 |
| `PROVISIONAL` | `部分完成`＋證據欄註明「裁決為暫定」 | 🔴 `GROK-R1-P1-01`：它是「**有主張、未定稿**」的已知中間態，**不是**「沒有證據」，故**不映** `狀態未確認` |
| `DONE`／票表之 `收案` | **僅為候選，不直接成終態** | 🔴 `CODEX-R1-P0-02`／`GROK-R1-P0-01`：r1 版讓 `收案` 自動成 `已完成`，會**把 `S2.1` 的已知旁路寫進 SoT 憲法**。須逐張驗三條件；未齊者降 `部分完成` |
| 票表之 `未開工`／`部分完成` | 同名對應 | 自動 |
| `OPEN` | **無自動終態映射**，但**可先行分桶** | 見下 |
| 無欄位（33 張） | 先標 `狀態未確認` | 不得猜 |

### 🔴 `OPEN` 之 tier-0 分桶（`COMPOSER-R1-P1-01`／`GROK-R1-P1-02`：人工量可大幅降）

r1 版 implied「只能全人工」**過強**。實測至少 **11 張**可先行分桶：
票表已有狀態者（9 張 `未開工` ＋ 2 張 `部分完成`）直接採票表值為**候選**，
再驗三條件。餘者才進人工盤點。

🔴 但 `CODEX-R1-P1-04` 的反面同時採納：**須先定義封閉的證據範圍（evidence universe）**，
否則「由缺席證明未開工」不成立，`狀態未確認` 會永久停留。
**證據範圍定義**（封閉，寫死於檢查腳本）：
`git log` 全史 ∪ `tests/` 之測試函式名 ∪ `handoffs/reconcile/*/synth.md` ∪ `docs/GOV*`。
範圍外的東西不得作為證據。

## `S0.3` 欄位與操作

### SoT 欄位（fact-key `governance-ticket-sot`）

| 欄 | 必填 | 內容 |
|---|---|---|
| `票` | ✅ | `S0.1` 全集內之識別碼 |
| `代號` | ❌ **選填** | 🔴 `GROK-R1-P2-04`：`B-1`…`B-5` 標題是腳本／檔名病徵、**無 `GOV-*` 代號**，必填會逼造假 |
| `狀態` | ✅ | `S0.2` 五值 |
| `證據` | ✅ | commit／測試名／收斂檔路徑；`狀態未確認` 填 `無`（**須落在證據範圍內**） |
| **`覆蓋`** | ✅ | 🔴 **新增**（`GROK-R1-P0-02`：r1 版定義在 `S0.2`、承載在 `S0.3` **斷裂**，`S0.4` 無法可證偽地寫出 `已完成`）。值為 `enforcement:<檢查ID>`／`waiver:<檢查ID>`／`無` |
| **`承接`** | ❌ | 🔴 **新增**（`GROK-R1-P1-05`／`COMPOSER-R1-P2-01`）：MERGE 之目標，如 `ticket:B-25`；backlog 索引區實有 `🔗 MERGE`，`刪減＝已作廢` 蓋不住 |
| `對外不得宣稱` | ❌ | 機器可讀之註解（沿用既有票表該欄） |

### 九種操作，各自唯一路徑（r1 版只列五種）

| 操作 | 路徑 |
|---|---|
| 新增票 | backlog 加 `## B-<n>` 標題與內文 ＋ SoT 加一列（**雙端不變式強制，缺一即紅**） |
| 刪減 | **不刪列**，狀態改 `已作廢`；backlog 內文保留 |
| 修改內容 | 只改 backlog 內文 |
| **元資料修改** | 只改 SoT 之 `代號`／`對外不得宣稱` |
| 註解 | 機器可讀者進 SoT；敘事進 backlog |
| **狀態變更** | **只改 SoT 一處** |
| **MERGE／承接** | 來源票狀態改 `已作廢`＋`承接` 欄填目標；目標票內文吸收 |
| **已作廢恢復** | 狀態由 `已作廢` 改回；`承接` 欄清空 |
| **投影再生成** | 🔴 `COMPOSER-R1-P1-04`：改 SoT 後**強制** `--write`，否則投影成為可手改副本。由既有產出端守衛在寫檔當下擋 |

🔴 `CODEX-R1-P1-05` 之 archival 規則：`已作廢` 列**永久保留**（不移出、不封存），
理由＝沿革可稽核；其 `證據` 欄須填裁決出處。
