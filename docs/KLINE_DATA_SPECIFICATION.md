# K線數據規格定義

## 文檔資訊
- **版本**: 1.0
- **最後更新**: 2025-10-20
- **適用範圍**: K線數據存儲、API、處理

---

## 核心設計原則

### First Principles分析

**根本需求**：存儲和處理不同市場、不同timeframe的K線數據，支援視覺化查看和ML訓練兩種用途。

**設計目標**：
1. **統一格式**：不同來源的數據映射到標準Schema
2. **高效存取**：支援快速讀取任意時間範圍
3. **多timeframe**：同時存儲1h/4h/12h/1d等多種粒度
4. **可擴展性**：未來可輕鬆加入新市場

## 標準K線數據Schema

### 核心欄位定義

每根K線包含以下欄位：

| 欄位名 | 數據類型 | 說明 | 範例 | 必需 |
|--------|---------|------|------|------|
| timestamp | int64 | Unix時間戳（秒） | 1717329600 | ✅ |
| open | float32 | 開盤價 | 3500.50 | ✅ |
| high | float32 | 最高價 | 3520.00 | ✅ |
| low | float32 | 最低價 | 3495.00 | ✅ |
| close | float32 | 收盤價 | 3510.00 | ✅ |
| volume | float32 | 成交量（基礎貨幣） | 1500.5 | ✅ |
| taker_buy_volume | float32 | 主動買入量 | 825.3 | ✅ |
| taker_ratio | float32 | 主動買入比例 | 0.55 | ✅ |
| quote_volume | float32 | 成交額（計價貨幣） | 5,265,000 | ⭕ |
| number_of_trades | int32 | 成交筆數 | 1250 | ⭕ |

**必需欄位（✅）**：所有市場必須提供
**可選欄位（⭕）**：部分市場可能無此數據

### 欄位說明

**timestamp**：
- 該K線的開始時間
- 統一使用UTC時區
- 秒級精度（不使用毫秒）

**OHLC**：
- 標準的開高低收四價
- 使用float32節省空間（精度足夠）
- 單位：該交易對的計價貨幣

**volume**：
- 成交量使用基礎貨幣單位
- 例如ETHUSDT的volume單位是ETH
- BTCUSDT的volume單位是BTC

**taker_buy_volume**：
- 主動買入的成交量（吃單）
- 用於計算市場情緒指標
- 單位與volume相同

**taker_ratio**：
- 計算公式：taker_buy_volume / volume
- 範圍：0.0 到 1.0
- 若volume為0，則設為0.5（中性）

**quote_volume**：
- 成交額，使用計價貨幣
- 例如ETHUSDT的quote_volume單位是USDT
- 用於過濾小市值交易對

## HDF5存儲結構

### 整體組織架構

```
kline_cache.h5
│
├── ETHUSDT/                    # Symbol分組
│   ├── 1h/                     # Timeframe分組
│   │   ├── data                # 實際K線數據（DataFrame）
│   │   └── metadata            # 元數據（屬性）
│   ├── 4h/
│   ├── 12h/
│   └── 1d/
│
├── BTCUSDT/
│   └── (同上)
│
├── SOLUSDT/
│   └── (同上)
│
└── _metadata/                  # 全局元數據
    ├── cache_index             # 快速查詢索引
    ├── version                 # 數據格式版本
    └── last_updated            # 最後更新時間
```

### 數據表結構（data）

**存儲格式**：Pandas DataFrame，使用HDF5 Table格式

**索引**：timestamp（已排序）

**壓縮**：使用zlib壓縮（level=5平衡壓縮率與速度）

**欄位順序**（優化讀取效率）：
1. timestamp（索引）
2. open, high, low, close（價格相關，常一起讀取）
3. volume, taker_buy_volume, taker_ratio（成交量相關）
4. quote_volume, number_of_trades（輔助欄位）

### 元數據結構（metadata）

每個timeframe的metadata屬性：

| 屬性名 | 數據類型 | 說明 | 範例 |
|--------|---------|------|------|
| time_range_start | int64 | 數據起始時間 | 1609459200 |
| time_range_end | int64 | 數據結束時間 | 1717329600 |
| total_bars | int32 | K線總數 | 5000 |
| last_updated | int64 | 最後更新時間 | 1717500000 |
| data_source | string | 數據來源 | "binance" |
| timeframe | string | 時間框架 | "1h" |
| is_complete | bool | 數據是否完整 | true |

**設計理由**：
- 快速判斷是否需要下載
- 檢查數據完整性
- 追蹤數據來源和更新時間

### 全局索引（cache_index）

用於快速查詢哪些symbol和timeframe已緩存：

```
{
  "ETHUSDT": ["1h", "4h", "1d"],
  "BTCUSDT": ["1h", "4h"],
  "SOLUSDT": ["1h"]
}
```

**更新時機**：
- 新增symbol或timeframe時
- 刪除緩存時
- 系統啟動時重建（驗證完整性）

## Timeframe規格

### 支援的Timeframe

**加密貨幣市場**：

| Timeframe | 說明 | 秒數 | 適用場景 |
|-----------|------|------|---------|
| 1m | 1分鐘 | 60 | 超短線、高頻 |
| 5m | 5分鐘 | 300 | 短線交易 |
| 15m | 15分鐘 | 900 | 短線交易 |
| 1h | 1小時 | 3600 | ML訓練、日內 |
| 4h | 4小時 | 14400 | 波段交易 |
| 12h | 12小時 | 43200 | 中期趨勢 |
| 1d | 1天 | 86400 | 長期分析 |

**台灣股市**（規劃）：

| Timeframe | 說明 | 秒數 | 備註 |
|-----------|------|------|------|
| 1m | 1分鐘 | 60 | 盤中可用 |
| 5m | 5分鐘 | 300 | 盤中可用 |
| 1d | 1天 | 86400 | 最常用 |

**美國股市**（規劃）：

| Timeframe | 說明 | 秒數 | 備註 |
|-----------|------|------|------|
| 1m | 1分鐘 | 60 | 需付費數據 |
| 5m | 5分鐘 | 300 | 需付費數據 |
| 1h | 1小時 | 3600 | 常用 |
| 1d | 1天 | 86400 | 免費可得 |

### Timeframe命名規範

**格式**：`{數字}{單位}`

**單位縮寫**：
- `m` = 分鐘（minute）
- `h` = 小時（hour）
- `d` = 天（day）
- `w` = 週（week，未使用）
- `M` = 月（month，未使用）

**注意事項**：
- 統一使用小寫（除月份M）
- 不使用複數形式（1h不是1hr）
- 與主要交易所API保持一致

## API數據格式

### 請求格式

**獲取K線數據**：

```
GET /api/v1/chart/data

Query Parameters:
- symbol: string (必需)
- case_timestamp: int64 (必需)
- timeframe: string (必需)
- max_bars: int (選填，預設200)

範例：
/api/v1/chart/data?symbol=ETHUSDT&case_timestamp=1717329600&timeframe=1h&max_bars=200
```

### 響應格式

**成功響應**：

```
{
  "success": true,
  "data": {
    "case_timestamp": 1717329600,
    "klines": [
      {
        "timestamp": 1717240000,
        "open": 3500.5,
        "high": 3520.0,
        "low": 3495.0,
        "close": 3510.0,
        "volume": 1500.5,
        "taker_buy_volume": 825.3,
        "taker_ratio": 0.55,
        "quote_volume": 5265000,
        "number_of_trades": 1250
      },
      // ... 更多K線
    ],
    "center_index": 100,
    "metadata": {
      "symbol": "ETHUSDT",
      "timeframe": "1h",
      "total_bars": 200,
      "time_range": {
        "start": 1717240000,
        "end": 1717329600
      }
    }
  }
}
```

**欄位說明**：
- `case_timestamp`：案例時間點T
- `klines`：K線陣列（已按時間排序）
- `center_index`：T點在klines陣列中的位置
- `metadata`：元數據資訊

### 錯誤響應

**數據不存在**：

```
{
  "success": false,
  "error": {
    "code": "DATA_NOT_FOUND",
    "message": "K線數據不存在",
    "details": {
      "symbol": "ETHUSDT",
      "timeframe": "1h",
      "requested_range": {
        "start": 1717240000,
        "end": 1717329600
      }
    }
  }
}
```

**常見錯誤代碼**：
- `DATA_NOT_FOUND`：數據不存在於HDF5
- `INVALID_SYMBOL`：symbol格式錯誤
- `INVALID_TIMEFRAME`：不支援的timeframe
- `TIME_RANGE_TOO_LARGE`：請求範圍超過限制
- `CACHE_READ_ERROR`：HDF5讀取失敗

## 跨市場數據映射

### 設計原則

不同市場的原始數據格式不同，需要映射到統一Schema。

**映射策略**：
1. 必需欄位：必須提供或計算
2. 可選欄位：盡量提供，無法取得則為null
3. 計算欄位：從原始數據計算得出（如taker_ratio）

### 幣安API映射

**原始格式**（API返回）：

```
[
  1717329600000,         // 開盤時間（毫秒）
  "3500.50",             // 開盤價
  "3520.00",             // 最高價
  "3495.00",             // 最低價
  "3510.00",             // 收盤價
  "1500.50",             // 成交量
  1717333199999,         // 收盤時間（毫秒）
  "5265000.00",          // 成交額
  1250,                  // 成交筆數
  "825.30",              // 主動買入量
  "2897250.00",          // 主動買入成交額
  "0"                    // 忽略
]
```

**映射規則**：

| 標準欄位 | 幣安欄位 | 轉換邏輯 |
|---------|---------|---------|
| timestamp | [0] | 毫秒轉秒：除以1000 |
| open | [1] | 字串轉float32 |
| high | [2] | 字串轉float32 |
| low | [3] | 字串轉float32 |
| close | [4] | 字串轉float32 |
| volume | [5] | 字串轉float32 |
| taker_buy_volume | [9] | 字串轉float32 |
| taker_ratio | 計算 | [9] / [5] |
| quote_volume | [7] | 字串轉float32 |
| number_of_trades | [8] | 整數 |

### 台股數據映射（規劃）

**預期來源**：證交所API或yfinance

**挑戰**：
- 無taker_buy_volume數據
- 只有日K線有完整數據

**映射策略**：

| 標準欄位 | 台股來源 | 轉換邏輯 |
|---------|---------|---------|
| timestamp | 日期欄位 | 轉換為UTC時間戳 |
| OHLC | 開高低收 | 直接映射 |
| volume | 成交量 | 直接映射（張→股） |
| taker_buy_volume | 無 | 設為null或volume*0.5 |
| taker_ratio | 計算 | 無法準確計算，設0.5 |
| quote_volume | 成交金額 | 直接映射 |

**注意事項**：
- 台股以「張」為單位，1張=1000股
- 需處理除權息事件
- 需處理交易日vs自然日

### 美股數據映射（規劃）

**預期來源**：IBKR API或yfinance

**特點**：
- 數據格式與加密貨幣類似
- 可能無taker_buy_volume（取決於來源）

**映射邏輯**：
- 與幣安類似的映射規則
- 時區轉換：美東時間→UTC
- 處理盤前盤後數據（可選）

## 數據品質保證

### 完整性檢查

**時間連續性**：
- 檢查時間戳是否有斷層
- 記錄缺失的時間段
- 提供補全功能

**數據合理性**：
- high >= max(open, close, low)
- low <= min(open, close, high)
- volume >= 0
- taker_ratio在0到1之間

**重複檢查**：
- 同一timestamp不應重複
- 發現重複時保留最新數據

### 異常值處理

**極端價格變動**：
- 單根K線漲跌幅超過50%標記為異常
- 記錄但不刪除（可能是真實暴漲暴跌）
- 提供過濾選項

**零成交量**：
- 允許存在（可能是休市或極低流動性）
- 計算指標時需特殊處理

**缺失值**：
- 必需欄位不允許null
- 可選欄位允許null
- 計算欄位若無法計算則設預設值

## 數據更新策略

### 增量更新邏輯

**更新觸發條件**：
1. 使用者請求的時間範圍超出現有數據
2. 數據超過24小時未更新
3. 使用者手動觸發更新

**更新流程**：
```
1. 檢查HDF5現有數據範圍
2. 計算需要下載的時間段
3. 從API獲取新數據
4. 驗證數據品質
5. 追加到HDF5
6. 更新metadata
```

**避免重複下載**：
- 檢查metadata的time_range
- 只下載缺失的時間段
- 重疊部分優先使用緩存

### 數據過期處理

**保留策略**：
- 完成數據永久保留（不自動刪除）
- 提供手動清理工具
- 可設定最大緩存容量

**原因**：
- ML訓練需要歷史數據
- 硬碟空間足夠（百GB級別）
- 避免重複下載節省時間

## 性能優化

### 讀取優化

**批量讀取**：
- 一次讀取連續時間範圍
- 避免多次小範圍讀取

**切片操作**：
- 利用HDF5原生支援的時間切片
- 不需讀取全部數據再過濾

**索引優化**：
- timestamp作為主索引（已排序）
- 快速定位特定時間點

### 寫入優化

**批量寫入**：
- 累積多根K線後一次寫入
- 減少I/O次數

**追加模式**：
- 使用append模式而非覆寫
- 保持數據順序

**壓縮策略**：
- zlib level=5（平衡壓縮率與速度）
- 壓縮比約3-5倍

## 數據安全與備份

### 安全措施

**檔案權限**：
- HDF5檔案僅本地訪問
- 無網絡暴露風險

**數據驗證**：
- 寫入前驗證格式
- 讀取後驗證完整性

**錯誤隔離**：
- 單一symbol失敗不影響其他
- 壞數據不寫入HDF5

### 備份策略

**建議方案**：
- 定期備份HDF5檔案到外部硬碟
- 使用版本控制（如git-lfs）
- 雲端備份（可選）

**恢復機制**：
- 檔案損壞時從備份還原
- 或重新從API下載

## 未來擴展考量

### 新市場加入

**步驟**：
1. 定義該市場的數據映射規則
2. 實作對應的DataProvider
3. 更新市場配置檔
4. 測試數據品質

**無需修改**：
- HDF5存儲結構
- 標準Schema定義
- API響應格式

### 新Timeframe支援

**條件**：
- 數據源提供該timeframe
- 有實際使用需求

**實作成本**：極低（只需配置）

### 數據增強

**潛在擴展**：
- 加入訂單簿數據（Orderbook）
- 加入資金費率（Funding Rate）
- 加入清算數據（Liquidation）

**設計彈性**：
- 可在metadata存儲額外資訊
- 不影響現有Schema

## 總結

本規格定義了K線數據的**統一標準**，確保不同來源的數據可以無縫整合，同時保證數據品質和存取效率。

**核心特點**：
- ✅ 統一Schema：10個標準欄位
- ✅ 多市場支援：加密/台股/美股
- ✅ 多timeframe：1m到1d共7種
- ✅ 高效存儲：HDF5壓縮與索引
- ✅ 增量更新：避免重複下載
- ✅ 品質保證：完整性與合理性檢查

**設計原則遵循**：
- ✅ 真實數據（從API獲取）
- ✅ 可擴展性（新市場易加入）
- ✅ 高效能（HDF5優化）
- ✅ 可維護性（清晰的結構）
