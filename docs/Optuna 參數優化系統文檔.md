# Optuna 參數優化系統文檔

## 一、系統概述

### 系統定位
量化研究工作平台 - 協助交易者從海量歷史數據中發現有效的交易策略

### 核心構想
不同於傳統量化平台的「策略→參數優化→回測」流程，本系統採用「案例探索→Pattern 發現→ML 優化→策略驗證」的創新路徑，透過機器學習自動發現市場中的盈利 Pattern

### 系統目標
- 從歷史數據中搜尋符合特定條件的案例（正例/反例）
- 使用技術指標，計算OLHC,VOLUME, TAKER RATIO，然後計算策略信號發生的次數，分析正反案例的信號密度特徵
- 透過 Optuna 優化引擎找出最佳參數組合
- 量化評估策略的有效性與穩定性

---

## 二、Optuna 優化系統架構

### 整體架構
採用三層設計：應用層（視覺化/ML 訓練）、服務層（Optuna 優化引擎/信號分析）、數據層（案例存儲/K 線數據）

### 優化引擎核心功能
- 自動搜索最佳策略參數組合
- 支援多種優化器（TPE、CmaEs、Random、GP、NSGA-II）
- 斷點續跑機制（SQLite 持久化）
- 並行多進程優化
- 智能錯誤重試與檢查點保存

### 優化模式
根據訓練窗口配置自動切換：
- **單密度模式**：僅分析近期窗口的信號密度
- **雙密度模式**：同時分析近期與遠期窗口，比較信號聚集程度

## 三、統計指標計算方法

### 單密度模式統計指標

**核心指標**
- **信號密度（Density）**：案例起漲點TO 前 N 根 K 線中符合策略的比例（0.0 ~ 1.0）
- **正例平均密度（Positive Avg Density）**：所有正例案例的平均信號密度
- **反例平均密度（Negative Avg Density）**：所有反例案例的平均信號密度
- **分離度（Separation）**：正例平均密度 - 反例平均密度（-1.0 ~ 1.0）

**統計檢驗指標**
- **P-value**：檢驗正反例密度分布的統計顯著性（< 0.05 視為顯著）
- **Cohen's d**：效果量大小（> 0.5 為中等效果，> 0.8 為大效果）
- **變異係數（CV）**：標準差/平均值，衡量穩定性（< 0.3 為穩定）

**計算方式**
1. 對每個案例，計算 案例起漲點TO 前 N 根 K 線的策略符合度
2. 匯總所有正例的密度值，計算平均值與標準差
3. 匯總所有反例的密度值，計算平均值與標準差
4. 計算 Separation = 正例平均 - 反例平均
5. 執行 t 檢驗計算 P-value，計算 Cohen's d 效果量

### 雙密度模式統計指標

**核心指標**
- **Near 窗口密度**：TO 前 N1 根 K 線的信號密度
- **Far 窗口密度**：TO 前 N2 根 K 線的信號密度（N2 > N1）
- **Near/Far Ratio**：近期密度 / 遠期密度，衡量信號聚集程度
- **正例 Near/Far Ratio**：正例案例的平均 ratio
- **反例 Near/Far Ratio**：反例案例的平均 ratio
- **Ratio Separation**：正例 ratio - 反例 ratio

**加權雙密度優化指標**
- **聚集得分（Clustering Score）**：正例 Near/Far Ratio - 1.0
  - Ratio = 2.5 → Score = 1.5（信號在近期聚集 150%）
  - Ratio = 1.0 → Score = 0.0（無聚集效應）
  - Ratio < 1.0 → Score < 0（懲罰近期信號更少的情況）
- **區分得分（Discrimination Score）**：Ratio Separation（正反例差異）
- **最終目標值**：聚集權重 × 聚集得分 + 區分權重 × 區分得分（預設權重各 0.5）

**計算方式**
1. 對每個案例，分別計算 Near 窗口與 Far 窗口的信號密度
2. 計算每個案例的 Near/Far Ratio
3. 匯總所有正例的 ratio，計算平均值
4. 匯總所有反例的 ratio，計算平均值
5. 計算聚集得分與區分得分
6. 根據設定權重計算最終目標值

## 四、Optuna 最佳 Trial 選擇機制

### 單目標優化（預設模式）

**優化方向**
- Direction = "maximize"（最大化目標值）

**選擇邏輯**
1. 收集所有 COMPLETE 狀態的 trials
2. 按目標值（Separation 或 加權雙密度得分）降序排列
3. 取目標值最大的 Trial 為最佳解

**API 調用**
- `study.best_trial`：返回目標值最大的 Trial
- `study.best_value`：返回該 Trial 的目標值
- `study.best_params`：返回該 Trial 的參數組合

**範例**
- Trial #1：目標值 = 0.35，參數 = {short: 5, mid: 15, long: 25}
- Trial #2：目標值 = 0.42，參數 = {short: 7, mid: 17, long: 28} ← 最佳
- Trial #3：目標值 = 0.28，參數 = {short: 3, mid: 14, long: 22}

結果：`best_trial = Trial #2`，`best_value = 0.42`

### 多目標優化（啟用時）

**優化方向**
- Directions = ["maximize", "maximize"]（同時最大化 Separation 與 Stability）

**Pareto 前沿概念**
- 無單一「最佳」Trial，而是一組非支配解（Pareto Front）
- Trial A 支配 Trial B 條件：A 在所有目標上 ≥ B，且至少一個目標 > B
- Pareto 前沿：所有不被其他 Trial 支配的 Trial 集合

**系統提供**
- `study.best_trials`：返回 Pareto 前沿所有 Trials（複數）
- `pareto_analyzer.get_knee_point()`：推薦膝點（平衡兩目標的最佳解）

## 五、優化目標判斷標準

### 單密度模式優質參數標準
- Separation > 0.3（正反例有明顯差異）
- P-value < 0.05（統計顯著）
- Cohen's d > 0.5（中等以上效果量）
- Stability CV < 0.3（穩定性佳）

### 雙密度模式優質參數標準
- Ratio Separation > 0.5（正反例 ratio 有明顯差異）
- 正例 Near/Far Ratio > 1.5（近期信號聚集明顯）
- P-value < 0.05（統計顯著）
- 正例 Ratio CV < 0.3（正例 ratio 穩定）

## 六、技術實現要點

### 參數搜索空間
- 動態根據策略元數據配置（支援 INT、FLOAT、CATEGORICAL 類型）
- 前端參數範圍優先於 YAML 預設範圍
- 自動驗證參數約束（如三線排列需 short < mid < long）

### 容錯機制
- 錯誤分類：可重試、不可重試、致命錯誤
- 指數退避重試策略
- 檢查點自動保存（每 50 次試驗）
- 進度監控與 ETA 預估

### 性能優化
- 支援多進程並行優化（n_jobs > 1）
- 使用 ThreadPoolExecutor 避免阻塞 event loop
- SQLite 持久化支援斷點續跑
- 智能剪枝機制（低於中位數時剪枝）

## 附錄：數值計算範例

### 單密度模式案例
**Trial #42 計算過程**
- 正例 10 個，信號密度：[0.75, 0.83, 0.67, ..., 0.79]，平均 0.76
- 反例 10 個，信號密度：[0.25, 0.33, 0.29, ..., 0.31]，平均 0.30
- 目標值 Separation = 0.76 - 0.30 = 0.46

### 雙密度模式案例
**Trial #88 計算過程（Near=24 根，Far=100 根）**
- 正例 Near 平均密度：0.80，Far 平均密度：0.38
- 正例 Near/Far Ratio 平均：2.1232
- 反例 Near 平均密度：0.31，Far 平均密度：0.40
- 反例 Near/Far Ratio 平均：0.7794
- 聚集得分 = 2.1232 - 1.0 = 1.1232
- 區分得分 = 2.1232 - 0.7794 = 1.3438
- 目標值（權重各 0.5）= 0.5 × 1.1232 + 0.5 × 1.3438 = 1.2335
