## §2 引用紀律（**即刻生效，不得只寫裸編號**）

🔴 **`B` 開頭有兩個空間，必須帶前綴區分**：

```
票 B-11        ← handoffs backlog 的票
批次 B1        ← epic TODO §B 的施工批次
```

**禁止**寫 `B11`／`B-1` 而不說明是哪一種。使用者已因此混淆一次
（原話：「不是只到 B4 嗎？為何你說 B11-B22，那 B5-B10 是什麼？」）。

**其餘空間**：`R<n>` 須註明所屬 epic；`V`／`M`／`S` 僅存在於 P16，跨文件引用須帶檔名。

---

### §2.1 🔴 2026-08-06 使用者裁定：**批次編號跨 epic 重複，帶「批次」二字仍不足以定位**

使用者原話：

> 「以前和現在有的就**釘死不要動**，以後產生的**一律用定義好的規則**，分類清楚寫好，
> 什麼地方用什麼訂清楚，不然第 0 批 B3.5、第 1 批 B1、票 B-35、未來第 1 批 B1，
> 這樣忽然講到 B1，誰能明確知道是什麼」

**問題比 §2 原本設想的更深**：§2 只解決「票 vs 批次」，
但**批次編號本身在每個 epic 內從 0 重新起算**（見 §1 第 2 列的配置規則）
⇒ 第 0 批的 `B1` 與第 1 批的 `B1` **是兩個不同的東西，字面完全相同**。
⇒ 寫「批次 B1」仍然無法定位。

**裁定（三段，逐條對應使用者的三句話）**：

| 使用者的話 | 落實 |
|---|---|
| 「以前和現在有的就釘死不要動」 | 既有 `票 B-01`～`B-38`、第 0 批 `B0`～`B7` **一律不改名**。模糊集合就此**封閉**，不再增長 |
| 「以後產生的一律用定義好的規則」 | 見下方 §2.2 表 |
| 「分類清楚寫好，什麼地方用什麼訂清楚」 | 每個空間的**唯一擁有文件**已列於 §1；本節補「往後新增時用哪個格式」 |

### §2.2 往後新增 ID 的規則（**提案，待 `票 B-26` 收斂裁定；未定案前不得單方採用**）

| 類別 | 往後格式 | 例 | 為何這樣訂 |

| **批次** | `<EPIC>-B<n>[<字母>]` | `GOVB0-B3`、`GOVB0-B3R`、`GOVB1-B1` | **必帶 epic 前綴**——這是唯一能區分「第 0 批 B1」與「第 1 批 B1」的方式 |

| **其餘** | 沿用 §1 | — | 無跨 epic 重複問題 |

⚠️ **本節是提案不是定案**。理由：規則增刪須由委員會依證據裁決（使用者定死），

## §3 配置前置（**新增任何 ID 之前必做**）

🔴 **盤點既有空間，貼出命令與輸出**：

```
M：  grep -oE '^\s*\| \*{0,2}M[0-9]+[a-z]?' <owner> | sort -u
V：  grep -oE '^\| \*{0,2}V[0-9]+' <owner> | sort -u
票： grep -E '^## B-[0-9]+' handoffs/20260801-GOV-AMEND-BACKLOG.md
R：  ls handoffs/reconcile/ | grep <epic>
```

⚠️ **抽取式必須涵蓋粗體變體**（`| **V13** |`）——2026-08-04 主委的 `^\| *V[0-9]`
**匹配不到粗體列**，數到 12 就宣稱完整，實際 15 列。

## §6 本檔的誠實邊界

- 本檔是**登記表**，不是檢查器。**目前無機械強制**——新增未登記樣式不會被擋。
  強制機制見 `票 B-24`。
- §1 登記 **12 個**空間，§4 另有 **2 個**（`E-<n>` 非 ID／`F<n>` 在用待補）
  ⇒ **實際流通 13 個 ID 空間**。由 2026-08-04 全量掃描導出（407+ 個相異值）。
  🔴 **不保證窮盡**——`F<n>` 就是掃描後**才**發現的，證明初版清單不完整；未來出現新樣式須補登記。
- `T<phase>-<類><n>` 的 `<類>` 集合（U/B/N/C/M/I/R/S/T）是**觀察值非設計值**，
  歷史上由各 epic 自行擴充，**尚未凍結**。
