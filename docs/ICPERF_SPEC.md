## §C 約束
- 解耦 7 條；不弱化 NaN／inf gate；PIT（不偷看未來）語意不變——第 t 根之標籤／排名只用 0..t，且**逐項照現行 oracle**：有效數＝非 NaN 數（±inf 計入）、分位只用有限值、排名歷史含 ±inf 且跳過 NaN；`MIN_SAMPLES`、`require_full_q`、`duplicates="drop"`、逐欄 q 選擇與 q=3 退回等規則逐一保留。逐位元相等之對象為**整數標籤、排名值與其下游統計量**；分位點之浮點值不作比對對象（探針證其無法逐位元重現，標籤可）。

## §B 四項平衡實測
- 🔴 **方向（使用者 2026-10-28）**：「所謂的四項平衡，是如何要更省時間或使用記憶體下降或精準度提高或檔案更小的方向去做，是有這樣的優化機會就要做，不是跟現況比沒比較差就不做」。⇒ Task 0.2 對每一入口除判準①–⑤外，另逐項列出四項之優化機會（時間：與實測下限之差距；記憶體：可省之複製、dtype 轉換、整表常駐；精確度：數值上更穩或更準之算法〔如累加順序、相關係數之兩段式算法〕；檔案大小：輸出與中間檔可省之重複或可壓縮處），凡有機會即列入施工，不以「不比改前差」為止。**不改值者**照 §G 逐位元相等驗收；**改值者**（精確度提高、輸出格式縮小）先實測改前改後之差異與受影響之下游判定，白話報使用者裁定後才改（量化結果之值由使用者裁定，見 §C）。
- **計算時間**：改前各段各元件之三點曲線（Task 0.2）對改後三點與全欄實跑（Task 5.2）；第 5 段每欄目標 ≤ 改前之 1/50；各段目標＝逼近 Task 0.2 實測之向量化下限（改後單位成本 ≤ 下限之 3 倍；逾則列原因與下一步，不以已達 1/50 為止）。
- **峰值記憶體**：門檻指標＝macOS `sample <pid>` 之 **Physical footprint**（與現行欄數上限之量測協定 `scripts/measure_ic_footprint.sh` 同一工具；該腳本檔頭與 `api/core/config.py:20` 明載禁用 ps RSS——壓縮頁面致同刻 RSS 與 footprint 差數十倍）；`scripts/scale_probe.py` 之行程樹 RSS 只作成長曲線之輔助、不作門檻。改前與改後一律以同一工具逐段記錄；**硬門檻只比同工具、同規模點**——改後三點各段峰值 footprint 不得高於改前同點同段，且依 Task 3.2 須逐段下降。全欄（20.9 萬欄）只有改後實測，改前全欄峰值無同工具實測，故全欄峰值與改前三點曲線之推算並列，門檻改由 Task 3.2／5.2 之 RAM × 0.5 判定。2D 核心各欄獨立，全欄時依欄分塊（每塊之欄數使 float64[T, 塊欄數] 與其排序歷史之工作記憶體有上限，上限值於 Task 0.2 以實測定並寫入收據），分塊不得改變任一欄之結果。
- **精確度**：改後逐位元等於凍結基準（§G），精度差＝0；任一不等即 FAIL。
- **檔案大小**：IC 輸出（summary_table、filter_log、結果檔）位元組不變；新增者只有凍結基準檔與收據。
