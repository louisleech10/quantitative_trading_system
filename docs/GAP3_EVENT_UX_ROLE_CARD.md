**出處**：使用者 2026-08-23 逐字「你跟委員討論看要怎麼做，能讓你出錯率最少且可以完成
SPEC/TODO/項目實作，就這樣去做」⇒ consult r3，三家 17 條全數 ACCEPT。
收斂檔：`handoffs/reconcile/20260823-gap3ux-x-consult-r3/synth.md`。

**病根**：七輪對抗審，主委自傷 **21 條**，其中約 **14 條**同一形態——
**改了某處之權威定義，未同步所有複述它的位置**。
R5 起改由委員指定修法、主委照抄，**技術決策因此零錯誤**，
但錯誤**轉移到整合**（R6 6/15、R7 7/12 皆為整合自傷）。
⇒ 本卡把「整合正確性」從主委的注意力移到結構上。

## 主委**不可做**

| 禁止 | 為什麼 |
|---|---|
| 在同一 commit 手改 **≥2 處對同一權威之複述**，而不附補丁包之 `SYNC-LOCI` | 14 條自傷之直接成因 |
| 自寫**第二處**複述（計數字面／集合等式／公式／enum 清單／reason 字面／mutation 條文） | 複述即第二份副本，副本必然漂移 |
| 自寫規範性驗證欄（改由委員之補丁包提供可紅之 mutation） | 曾寫出恆綠之空斷言（`grep -c "shift(-" == 0`） |
| **為降噪而收窄自製機械閘之掃描面** | R6 收窄 ⇒ R7 三條從縫隙漏出；收窄之理由本身是錯的 |
| 寫「已修／已同步」而**未附 locus 或 commit** | 曾在檔頭寫「future72 單位已修」而 §D 未改 |
| 凍前**手拆** SPEC 正文 | 三家一致否決；搬運＝錯誤率最高之動作 |

## 主委**必須做**

| 動作 | 機械對證 |
|---|---|
| 套用補丁後跑 `bash scripts/gap3ux_pre_review.sh <patch.md>` | rc=0 才可派審。🔴 **閘之權威清單唯一在該腳本內，任何文件（含本卡）一律不寫閘數** |
| 觸及 SPEC 之 commit，須存在對應 `handoffs/patches/*.md` 或明示 ERRATA id | `patch_locus_check.py` |
| 變更任何閘之掃描面，須附「灌回舊 bug 轉紅」之 receipt | 反測輸出入 commit message |
| 對不確定處**具名標「待下輪裁定」** | 已驗證有效（R5 標的 `time_range`，R6 三家即打穿） |
| 於 brief 具名標示「本批改寫未經任何審查」 | 已驗證有效（R4／R5 自傷皆因此被抓出） |
| 每輪回報**並列**自傷絕對數與佔比 | 佔比在真缺口下降時會自動上升，單看會誤導 |

## 主委保留之職權
開門閘 token／派工／HANDOFF 索引／**接受或拒絕整包補丁**／標「未經審查」／
與使用者溝通／發起 errata。

## 委員之新交付物：補丁包（R9 增訂 stage 後綴與 anchor 字面閘）

檔名：`handoffs/patches/<日期>-<epic>-<輪次>-<cluster>.md`

```markdown
# PATCH cluster <名>
AUTHORITY: <哪一處是權威定義>
SYNC-LOCI:
- <檔>#<可 grep 到的字面錨點>            # 缺 stage 後綴 ⇒ 預設 @spec
- <檔>#<字面錨點>@doc                    # 白話說明／角色卡等
- <檔>#<字面錨點>@harness                # 治理腳本／測試
- <檔>#<字面錨點>@impl                   # 實作階段才會動到的產品程式碼
BEFORE/AFTER: <可直接套用之替換或 unified diff>
VERIFY:
- <可跑之命令>
```

🔴 **anchor 必須是字面（R9 裁定；三家一致）**：`patch_locus_check.py` 於 parse 當下即
以「該 anchor 是否出現在該檔**當前內容**」判定，找不到 ⇒ **補丁包格式錯，rc=2**。
R8 曾有敘述型 anchor（`#檔頭 A-6／FROZEN 句`／`#§A-A-6`／`#§G-G-2`）——
那些字串在檔內根本不存在 ⇒ 實質改完了閘仍紅，且紅得沒有資訊。

🔴 **stage 是補丁包之責任宣告，不是呼叫端的降噪開關（R9 三家裁定）**：
未達之 `@impl` 列為 **DEFERRED、不計 rc**（凍前不實作）；
呼叫端只有 `--also-impl` 這個**加寬**旗標，**不得**新增任何「只檢查某 subset」之旗標。
缺省 stage ＝ `@spec`（最嚴）⇒ 忘了標的行為與 R8 完全相同，不放寬。
⚠️ 誠實邊界：委員若把 spec locus 誤標 `@impl`，本閘看不見 ⇒ 與 anchor 精確度同類，
屬委員責任，保留獨立審查（見下「做不成機械閘者」）。

🔴 **commit 後複驗須帶 `--diff-base <套用前 ref>`**：對乾淨 worktree 跑無 base 之檢查，
會把**已落地**之 locus 誤報為「檔案未被本次改動」——那是方法論假紅。

**責任歸屬（三家明訂）**：
- 補丁包**漏列** locus ⇒ **補丁包紅，算委員責任**，不算主委自傷。
- 已列而主委**未改齊** ⇒ 主委套用不完整，補改後重跑。
