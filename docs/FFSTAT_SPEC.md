## §C 約束
- **逐欄檢定**：開啟 fracdiff 或 ADF 差分時，進入該步驟之每欄皆以其校準值做 ADF 判定；不設任何免檢清單。名稱不得參與任何平穩化之判定。刪 `utils/adf_safe_skip.py` 之判定用途與 `ADFSafeSkipConfig`（含 `additional_patterns`／`exclusion_patterns`）；設定帶此段 ⇒ 設定驗證拒收並指名已移除。
- **目標層**：fracdiff 目標層（L1、L2，寫死）只取自結構化層來源——frame 路徑 `_column_layer_map`、CGSA 路徑群組之 `layer`；對照缺欄或無對照 ⇒ fail-closed（指名缺漏欄數與示例）；刪 `_FRACDIFF_LAYER_RE` 欄名解析退路。
- **`apply_to` 封閉**：`ADFDifferencingConfig.apply_to` 與 `FractionalDifferencingConfig.apply_to` 只收 `non_stationary`、`all`；regex、欄名清單、`layer1_only` 於設定驗證拒收（訊息指名只收二值）；刪 `_select_columns` 之 `layer1_only` 分支。winsor、rank 等縮放步驟不在本票（§N）。
- **校準資料無洩漏**：ADF 差分候選、fracdiff 目標篩選、d\* 搜尋三路之校準值，只取**該 symbol、該原生週期、輸出起始日之前**之資料（每欄最後 N 個有效值，N＝校準長度），且該段不進入公開輸出與任何切分。
- **兩個資料域**：開啟平穩化時，另建**校準資料域**——以較早之載入起點（`calibration_ingest_start`，見下式）對同一設定計算進入 L6.5 之各層特徵，只取輸出起始日之前之列作校準值；**公開資料域**照現行自輸出起始日（或 B6 之 ingest 起點）計算與落盤，值不因校準域而變。校準域不寫 CGSA registry、不入 resume checkpoint、不落盤，只在記憶體中供 L6.5 查校準值；與 `FFACT_WARMUP_TRIM` 解耦（其預設 `0` 不改）。校準域不依資料剔欄（L3 死欄過濾不剔；L5 參考標的與前史切片無重疊時保留已設定之 cs 欄、值全 NaN，依下方前史不足逐欄處理——v20）；公開域之欄在校準域缺欄（欄定義不符）⇒ fail-closed。兩域之時間比較（公開 L0 起訖、warmup 裁切、校準邊界）同一換算：無時區之時間視為 UTC、有時區者轉 UTC（v20，轉接器回傳有時區 index 之市場亦同）。校準域於**獨立之 `FeatureFactory` 實例**計算，與公開域不共用任何實例內狀態或快取（含 L5 參考標的快取 `_reference_data_cache`）；各層所用之模組層級快取（程序內跨實例共享者）於實作時逐一盤點並登記於收據，其鍵須含載入時間窗，否則兩域不得使用之。
- **校準域之資源界線**：校準域之輸入（L1–L6 之計算輸入）只含 `[calibration_ingest_start, 輸出起始日)` 之前史切片（不含輸出範圍）；讀取沿用 L0 之整份讀入後遮罩（儲存層 `read_klines` 本即整份讀入再於記憶體過濾，傳時間界線不降 I/O 與瞬間峰值），整份 frame 於讀取函式內釋放、只回傳起始日前之列，起始日前原始列只留一份（v20）；**先於公開域**計算，截取每欄起始日前最後 N 個有效值後即釋放各層中間結果，不與公開域之各層同時駐留；其大層暫存 memmap 寫在獨立暫存目錄、截取後即刪（例外時亦刪）。峰值記憶體以真實冷 run 驗（Task 4.1），不得以「N／公開列數」比例推估。
- **校準前置關卡**：開啟平穩化時，校準為一次生成之**第一步**——對本次**會進入 L6.5 之全部原生週期**（含 resume 時 L1–L6 已完成、本次不重算但仍進 L6.5 之週期）完成校準域計算、截取與有效值檢查，才進行 `_prepare_cgsa_registry`、主週期任何層之落盤與多週期 worker 之啟動；worker 不自行重算校準。
- **校準封包**：每個原生週期之校準結果為一個封包，**只由前置關卡產生**（不接受任何呼叫端提供之封包或校準值），含身分鍵（symbol、原生週期、輸出起始日、設定 hash、N、欄集合指紋）、每欄之最晚校準時間與校準值，以及來源紀錄 `calibration_source_sha256`＝該週期前史切片 `[calibration_ingest_start, 輸出起始日)` 之 K 線依下列位元組框架之 sha256：①表頭＝各來源欄名依 UTF-8 位元組升序排列、以 `\n`（0x0A）連接之 UTF-8 位元組，後接 `\n\n`；②表身逐列（時間戳升序、列優先），每列＝時間戳 int64 奈秒小端 8 位元組，接各來源欄（同表頭次序）之 float64 小端 8 位元組；③任何 NaN 一律寫為 `0x7FF8000000000000`（小端），±inf 依 IEEE-754 原樣；由前置關卡從其實際讀入之切片計算，記入 manifest 與收據供重現（封包只在本次 run 內產生與使用，此紀錄不作身分核對項）；L6.5 使用前逐項核對身分鍵與當次公開域一致，且每欄最晚校準時間早於輸出起始日；不符或缺封包 ⇒ 零寫入失敗，錯誤訊息指名週期、欄與不符之身分欄位（或校準時間）。多週期 worker 只接收其自身週期之封包。
- **校準域錯誤不可降級**：校準域之載入、各層計算、截取、對齊任一步驟之例外（含缺欄、該週期輸出起始日之前全無 K 線；**逐欄有效值不足 N 不在此列，見前史深度**），皆為**生成失敗**——不經 `_execute_l65_with_degradation`、`_safe_execute` 或 `allow_partial_layers` 之降級路徑；因校準為前置關卡，任一週期失敗時整個 run 目錄與 registry 皆零寫入；不得回退用輸出範圍內資料校準。
- **前史深度**（v22 註：此深度為保守上界——實測「warmup 估計」與「首個有效值延遲」有重疊，偏大只會多讀、實際前史短於深度即自資料起點載入；Task 2.1 以之定載入起點（稀疏欄不足時加倍），Task 2.3 只以其基礎式〔不含加倍〕定主週期起點並與「保住主週期 N 根輸出」之上限取較早，見「未填起始日」）：`calibration_ingest_start`＝輸出起始日往前 `estimate_max_warmup_bars`（依原生週期）＋ N ＋ 該週期之首個有效值最大延遲（以輕量真實 run 量得並登記於設定常數，Task 2.1 邊界④驗）根；實際前史短於此深度時自資料起點載入，稀疏欄（值常為 NaN 者）於此深度內有效值不足 N 時深度加倍至不再不足或達資料起點。某欄於輸出起始日之前之有限值少於 N（使用者 2026-09-26 裁定）⇒ **該欄不做平穩化**（不 fracdiff、不 ADF 差分、保留原值），其決策記事件 `calibration_insufficient_history` 並列缺少根數，事件經 `apply_quality_degradation` 之 `extra_failure_reasons` 併入 `failure_reasons`（`<事件>:<欄數>`）使品質降為 `partial`，其餘欄照常；該欄公開序列亦全無有效值者（如結構恆為 NaN 之欄）只記未檢定事件；不得縮窗、不得以不足 N 之值判定、不得退回用輸出範圍內資料。該週期輸出起始日之前全無 K 線 ⇒ 生成失敗（零寫入）。
- **未填起始日**（使用者 2026-09-24 裁定；v21 推算方式依使用者 2026-09-26 裁定）：開啟平穩化而請求未帶 `start_date` 時，自動推算**有效起始日**：
  - **只依主週期**（v23，使用者 2026-09-26 再裁定「以主訓練週期優先、次週期能做多少就做」）：次週期（非主週期之原生週期）不參與起點推算。**主週期**（v25）＝`config.timeframes.primary`，即特徵工廠介面之主訓練週期（介面 `TimeframeSelector` 使其恆在 training 內，並使生成請求之 `timeframe` 與之一致）。自動推算前先驗：primary 須屬本次原生週期集合（training 去重）；本次只有一個原生週期時，`generate_features` 之 `timeframe` 須等於 primary——任一不符 ⇒ 於任何寫入前 fail-closed，訊息指名 primary、`timeframe` 與原生週期集合（不猜）。N_主、前史深度基礎式與上限皆依主週期。`run_ic_first` 不支援自動起始日：其輸出窗只來自同一 factory 先前之生成；平穩化開啟而無輸出窗 ⇒ 前置關卡前拋 `CalibrationError`（field＝output_start）、零寫入。
  - **上限（保住主週期輸出）**：「至結束日之主週期列」＝公開 L0 以同一 `end_date`（未填＝資料末端）經同一換算（`to_utc`、同一端點包含規則）篩出之主週期列；其倒數第 N_主 根之時間為上限（N_主＝主週期之 N，依 `calibration_bars_by_timeframe` 取主週期值，隨 N 變）。該列數＜N_主 ⇒ fail-closed，訊息列出可用與需要根數。
  - **主週期起點**：主週期實際 K 線列（依實際存在之列計數，缺口不補、不以固定秒數換算）以 0 起算之索引 `前史深度_主` 那一列之時間；`前史深度_主` 只用下方 §C 前史深度之**基礎式**（`estimate_max_warmup_bars(config, 主週期, [主週期])`＋N_主＋延遲常數，皆以主週期自身根數計；同 Task 2.1 對該週期之呼叫，不經 `resolve_output_window`），**不含**前置關卡載入時之稀疏欄加倍（加倍依特徵值，只影響 Task 2.1 之載入、不影響有效起始日）；主週期列數 ≤ `前史深度_主` ⇒ 起點取上限。
  - **有效起始日**＝min(主週期起點, 上限)；取上限者 `auto_start_capped=True`，此時湊不滿 N_主 之主週期欄於前置關卡依 v19 處理。
  - **次週期**：前置關卡照 Task 2.1 逐欄以其自身 N 處理——起始日前有效值足者照常平穩化，不足者依 v19 記 `calibration_insufficient_history`、品質 partial；某次週期於有效起始日前全無 K 線 ⇒ 依 §C 前史深度之規則零寫入失敗並指名週期。
  - 因果性：有效起始日只依設定（前史深度基礎式、N_主）、主週期 K 線列數與結束日決定，不讀任何特徵值、不計算校準域；故改動任何 K 線值不改變有效起始日。
  - 其餘：此推算於請求入口、**計算設定 hash 與任何快取查詢之前**完成，設定 hash 與快取鍵含有效起始日與 `output_start_source`，之後一律視同使用者給了此起始日（校準只用其之前、公開輸出自其開始）；manifest 與生成結果 metadata 記具名鍵 `effective_output_start`、`output_start_source`（`user`｜`auto_reserved_calibration`）、`auto_start_primary_start`（主週期基礎深度那一列之時間；主週期列數 ≤ 基礎深度時為 null）、`auto_start_capped`（次週期前史不足之欄數沿用 `failure_reasons` 之事件計數）；前端於生成結果顯示「特徵自 X 起（前段保留供校準）」，截停時另註「部分欄歷史不足，未做平穩化」。自動推算只做主週期 index 查列（不計算校準域），單次 ≤ 2 秒。平穩化關閉時未填起始日之行為不變。
- **三路同一有效長度**：同一原生週期內三路 ADF 皆以同一 N 為樣本數（刪 d\* 內層寫死之 500、parallel 與循序同值）；N 可依原生週期分設，預設皆 500，最終預設依 §A 使用者裁定；收據逐欄記校準時間範圍、N、ADF p 值、決策。
- **d\* 三出口**（循序與 parallel 同語義；含磁碟層 `_d_star_cache.py`）：①快取讀取失敗——`DStarCache` 載入時 `OSError` 或內容損壞（檔案不存在為正常冷快取），或單欄 `cache.get` 例外 ⇒ 事件 `dstar_cache_read_failed`，受影響欄視為未命中並照常搜尋；之後 flush 以新內容覆寫損壞檔；同路徑兩 run 交錯 flush 沿用「最後寫入者勝出」，不發事件；②搜尋例外 ⇒ 該欄**保原值**——不套用 fracdiff、同輪排除於 ADF 差分候選、不寫快取，事件 `fracdiff_search_failed`；③快取寫入失敗——單欄 `cache.set` 例外或 `flush_atomic` 之 `write_text`／`os.replace` 失敗（改為回報結果）⇒ 已得之 `d` 照常套用，事件 `dstar_cache_write_failed:<受影響欄數>`。parallel 主程序**先判 worker `status` 再寫快取**。事件經 `apply_quality_degradation` 新增之 keyword 參數 `extra_failure_reasons: Sequence[str]` 併入 `failure_reasons` 並使品質降為 `partial`——CGSA 串流 writer 於 manifest 合併前、frame 路徑於 factory persist 前、`_resolve_completeness_without_manifest` 各傳入同一事件。不得以任何預設 `d` 替代。
- **d\* 快取鍵**：含校準值指紋與 N（現行 `_compute_fracdiff_hash` 已含 `calibration_bars`，須改為實際 N 並確認含值指紋）；校準資料改變即未命中。
- 不改 fracdiff 層範圍（L1、L2）。特徵欄數、列數不變；每欄之平穩化決策與所用 `d` 由收據逐欄列出。
