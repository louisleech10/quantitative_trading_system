✅ B7 收案（2026-08-10）— claude 段收窄

原本的毛病

派工閘用一條子字串比對判斷「你是不是在派子代理」：句子裡有 claude 這個字、 後面又出現 -p 或 --print 這兩串字元，就擋。

問題是 .claude/ 是治理目錄、/private/tmp/claude-501/ 是暫存區， 路徑裡本來就有 claude；而 git rev-parse 裡藏著 -p、git status --porcelain 裡藏著 --p、 find … -print 更是直接命中。⇒ 四種每天都在用的唯讀指令被擋。

改成什麼

要同時滿足四件事才算派工：

  1. claude 必須站在命令位置（句首或分隔符後，可帶路徑前綴）
  2. -p／--print 必須是獨立旗標，而且在 claude 後面、同一段裡
  3. 命令名如果可能被殼層展開（$(…)、`、!、萬用字元…）⇒ 退回舊的寬鬆比對（寧可誤擋）
  4. 前處理要先把「引號裡的換行」「反斜線續行」「反斜線跳脫」按 bash 的真實語意處理掉

結果：6 條誤擋全部放行，16 條判定不變，沒有任何一條真派工被放掉。

  • 同一行重複標籤，空的外層欄位可以「借用」內層的內容過關。

本來的病
