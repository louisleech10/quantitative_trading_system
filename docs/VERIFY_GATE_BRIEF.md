# 驗收防偽閘 — 給使用者的簡述決策文件

## 一句話
讓「已驗 / 真紅 / 測試通過」這種話，**沒有真實跑測試的收據就寫不進交接文件和 commit**——機器擋，不靠人記得。

## 為什麼要做（這次事故）
P0-FF-3 的交接文件寫了「對齊測試已驗證通過」，但其實**那個慢測從來沒真的跑過**——有人把「只跑了 0.38 秒的快速檢查」寫成了「完整驗證通過」。我這次第一次真跑，立刻發現它是紅的。
治理系統其他環節都正常運作（委員都老實說「我沒跑慢測」），唯一破口是**寫交接的人沒跑就宣稱跑了**，而且**目前沒有任何機器檢查會擋這種話**。

## 這個閘要怎麼擋（白話）
1. **跑測試 = 自動開收據**：以後跑驗證測試，工具自動產一張「收據」，記下：跑了什麼指令、哪些測試、花多久、過還是沒過、log 指紋。
2. **寫『已驗』要附收據**：交接文件或 commit 裡只要出現「已驗 / 真紅 / 通過 / 無未來函數」這類話，旁邊**必須**有對應收據編號；機器會核對收據是不是真的、範圍對不對。
3. **快測收據不能冒充慢測**：0.38 秒的快速檢查收據，**不能**拿來撐「慢測通過」的話——這正是這次被鑽的洞。
4. **commit 前自動攔**：寫了沒收據的「已驗」就 commit 不過去（連 docs 改 HANDOFF 也要過，因為這次出事的正是 docs）。

## 誠實邊界（這閘擋得了什麼、擋不了什麼）
- **擋得了**：沒跑就宣稱、快測冒充慢測、commit 夾帶假驗收。
- **擋不了**：收據是真跑出來的、但人對結果的「解讀」錯（例如把紅看成綠）。那一層還是靠 adversarial + 委員複核。閘只保證「有真跑、範圍對得上」，不保證「結論詮釋正確」。
