### 強制機制設計（**不得靠紀律與記憶**——使用者 2026-08-02 定，2026-08-07 重申）

🔴 **原提案已被使用者當場推翻**：主委原設計為「寫『唯一有效』時加一行來源標記」，
兩個缺陷：①**靠主委記得寫** ②「權威宣稱詞」是**禁止清單**，永遠列不完（＝`票 B-23` 的同一個病）。

**改後設計——不偵測「寫了什麼」，偵測「兩份對不上」**：

| 層 | 元件 | 行為 |
|---|---|---|
| 資料 | 順序存於單一資料檔 | 唯一可手改處 |
| 投影 | 各文件的順序段由生成器產出，帶邊界標記 | 手改即偏離 |
| 檢查 | `fact_key_check.sh`：重新生成並 diff | 不一致 ⇒ rc=1 |
| 強制 | **pre-push hook**（與 `plain_docs_sync_check.sh` 同位置） | rc≠0 ⇒ **拒絕 push** |

**為何不靠記憶**：手改文件 ⇒ diff 不符 ⇒ 擋；忘記跑生成 ⇒ diff 不符 ⇒ 擋。
**無任何一步需要記得寫標記。** 選 pre-push 的依據＝該位置的既有機制**已實測擋下主委 2 次**。

**誠實邊界**（具名，不解）：
- 在**生成器不知道的新文件**裡憑空手寫第三份副本 ⇒ 擋不到。
  便宜的部分解＝掃 generated block 之外出現 ≥3 個票號同段者並 flag；
  屬啟發式，**須附誤擋率 receipt 才可上線**（與 `票 B-23` 同紀律）。
- `git push --no-verify` 可繞。與現有機制同一邊界。
