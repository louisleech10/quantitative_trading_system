## 系統總覽

### XGBoost 批量分析的目的

本系統使用 XGBoost 機器學習演算法，從歷史交易案例中自動發現獲利模式。

**核心概念：**
- 輸入：K 線數據 + 技術指標配置
- 輸出：特徵重要性 + 決策規則 + 模型性能評估

### 重要說明

⚠️ **XGBoost 分析是對「所有案例」進行批量分析**，而非單一案例。系統會：
1. 讀取所有符合條件的案例（正例 + 反例）
2. 根據指標配置計算特徵
3. 訓練模型找出區分正例和反例的關鍵因素

## 詳細操作步驟

### Step 1: 進入 XGBoost 分析頁面

**路徑選擇：**
- 直接訪問：http://localhost:3000/patterns/xgboost-analysis
- 或從首頁：點擊「樣式發現系統」→ 點擊「🧠 XGBoost 分析」按鈕

### Step 2: 查看案例統計

頁面左上方會顯示「案例資料統計」卡片：

| 項目 | 說明 |
|------|------|
| 總案例數 | cases.json 中的案例數量 |
| 正例 | positive_case = 1 的案例 |
| 反例 | positive_case = 0 的案例 |
| 可用交易對 | 例如：ETHUSDT |
| 可用週期 | 例如：12h |

✅ **驗證點**：確認案例數量正確（例如 205 個案例）

### Step 3: 選擇數據範圍

在「數據選擇」卡片中：

1. **交易對**：從下拉選單選擇（如 ETHUSDT）
2. **時間週期**：選擇 K 線週期（如 12h）
3. **回看 K 線數量**：每個案例需要多少根歷史 K 線（預設 200）
4. **交叉驗證折數**：CV 折數（預設 5）

### Step 4: 配置技術指標

在「指標配置」卡片中：

**預設已有一個 EMA 三線順勢指標**

可配置的指標類型：
| 指標 | 參數 |
|------|------|
| EMA 三線順勢 | ema_short(5), ema_mid(20), ema_long(60), volume_threshold(0.6) |
| RSI | period(14), overbought(70), oversold(30) |
| MACD | fast(12), slow(26), signal(9) |

**操作說明：**
- 點擊「添加指標」新增更多指標
- 點擊垃圾桶圖標刪除指標
- 點擊「預覽特徵」查看將生成的特徵名稱

**建議配置範例：**
```
指標 1: EMA 三線順勢
  - 數據源: Close
  - ema_short: 5
  - ema_mid: 20
  - ema_long: 60

指標 2: RSI
  - 數據源: Close
  - period: 14
  - overbought: 70
  - oversold: 30
```

### Step 5: 執行分析

點擊「開始分析」按鈕後：

1. 系統會顯示進度條
2. 依次執行：
   - 計算時間範圍
   - 讀取 K 線數據
   - 計算指標特徵
   - 為每個案例提取特徵
   - 訓練 XGBoost 模型
   - 計算特徵重要性
   - 提取決策規則
   - 儲存模型

⏱️ **預估時間**：200+ 案例約 30-60 秒

### Step 6: 查看結果

分析完成後，右側會顯示完整結果：

#### 6.1 分析摘要
- 交易對、時間週期
- 有效案例數
- 生成特徵數
- 模型儲存狀態

#### 6.2 模型性能
| 指標 | 說明 | 良好範圍 |
|------|------|---------|
| 訓練 AUC | 訓練集 AUC | > 70% |
| CV AUC | 交叉驗證 AUC | > 65% |
| Precision | 精確率 | > 60% |
| Recall | 召回率 | > 60% |
| F1 Score | F1 分數 | > 60% |
| 過擬合程度 | 訓練-CV 差距 | < 10% |

#### 6.3 特徵重要性 (Top 15)
- 顯示最重要的 15 個特徵
- 條形圖視覺化重要性
- 重要性越高 = 對預測越有影響

#### 6.4 決策規則 (Top 10)
- 顯示 XGBoost 發現的決策規則
- 包含：支持度、信心度、提升度
- 例如：`price_momentum_3 > 0.02 AND volume_ratio > 1.5`

## 結果解讀

### 如何使用特徵重要性

**重要性高的特徵 = 對區分正/反例最有幫助**

範例解讀：
```
排名 1: price_change_pct (15.2%)
  → 價格變化百分比是最重要的特徵
  
排名 2: close_ema5_value (12.8%)
  → 收盤價相對 EMA5 的位置很重要
  
排名 3: volume_ratio_5 (10.5%)
  → 成交量相對 5 期平均的比率重要
```

### 如何使用決策規則

決策規則可以直接轉換為交易條件：

```
規則: price_momentum_3 > 0.02 AND rsi14_value < 40
支持度: 85
信心度: 72%
提升度: 2.3

解讀：
- 當 3 期價格動量 > 2% 且 RSI14 < 40 時
- 有 85 個案例符合此條件
- 其中 72% 是正例（獲利案例）
- 提升度 2.3 表示此規則比隨機猜測好 2.3 倍
```

### 模型品質判斷

| 情況 | 判斷 | 建議 |
|------|------|------|
| CV AUC > 70%, 過擬合 < 5% | ✅ 優秀 | 可信任結果 |
| CV AUC 60-70%, 過擬合 < 10% | 🟡 可接受 | 結果有參考價值 |
| CV AUC < 60% 或 過擬合 > 15% | ❌ 不佳 | 調整指標重試 |

## 常見問題

### Q1: 顯示「找不到案例」

**原因**：選擇的交易對/週期沒有對應案例

**解決**：
1. 檢查案例統計中的「可用交易對」和「可用週期」
2. 確保選擇有案例的組合

### Q2: 分析時間很長

**原因**：K 線數據量大或案例數多

**解決**：
1. 減少「回看 K 線數量」（如改為 100）
2. 確保 HDF5 緩存已有數據

### Q3: CV AUC 很低

**原因**：指標配置可能不適合當前數據

**解決**：
1. 嘗試不同的指標組合
2. 調整指標參數
3. 增加更多指標

### Q4: 特徵重要性都很低

**原因**：可能沒有明顯的區分特徵

**解決**：
1. 檢查正/反例比例是否平衡
2. 嘗試不同的指標類型
3. 考慮案例品質問題

## 技術細節

### API 端點

| 端點 | 方法 | 用途 |
|------|------|------|
| `/api/v1/pattern-analysis/cases/summary` | GET | 獲取案例統計 |
| `/api/v1/pattern-analysis/xgboost/batch/start` | POST | 啟動批量分析 |
| `/api/v1/pattern-analysis/xgboost/batch/task/{id}` | GET | 查詢任務狀態 |

### 數據流程

```
1. 前端發送 POST 請求 (symbol, timeframe, indicators)
2. 後端建立異步任務
3. 後端從 HDF5 讀取 K 線
4. 後端計算指標特徵
5. 後端為每個案例提取特徵 + 標籤
6. XGBoost 訓練和評估
7. 返回結果
```
