> 「主委只套用『刪殘／改型別』的修訂、**不再引入新抽象／新承載／新序列化器**；若違反則改估 2 輪以上。」

## 這輪委員抓到什麼（6 群，全部已修）

| 抓到什麼 | 白話 |
|---|---|
| 三家都抓：**改了型別，用法沒跟著改** | 我把一個資料結構從「字典」改成「不可變序列」，但規格裡好幾處還在用字典的寫法（`windows[事件編號]`）。照著寫會直接壞掉 |
| 兩家抓：**標題行還寫舊型別** | 同一段的標題寫「字典」、內文寫「序列」。實作者只會看標題那行，照做就把我上一輪加的防護整個打穿 |
| 一家抓：**欄位清單漏列一欄** | 同一個 Task 裡，「這個物件恰好有這幾欄」的清單少列了一欄，而下面又要求那一欄存在——自相矛盾 |
| 兩家抓：**兩端型別不同，卻沒說怎麼轉** | 上游存「序列」、下游收「字典」，全文沒有一處說怎麼換。實作者會自己發明規則，或乾脆把上游改回去 |
| 一家抓：**旁白還在用舊詞** | 正文改了型別，旁邊的說明還寫「唯讀映射」——並存會誘導實作走回頭路 |
| 一家抓：**「掃整個前端目錄」不是機械檢查** | 範圍可以被繞開（改名、搬檔、動態載入）。改成枚舉「產生雜湊的入口」——入口是有限的，位置不是 |
