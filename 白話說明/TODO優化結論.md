## 這票做了什麼

**以前**：每張票的「施工清單」（TODO）是一份中文散文 `docs/X_TODO.md`。
人和委員會讀它，但**電腦不檢查它**——寫了「要測某某」，實際有沒有測，只能靠人記得。
先前的診斷查出：實作出的錯，約四成是「規格寫對了，但沒照做」，而散文清單正是這類錯的溫床。

**現在**：新票的施工清單不再寫散文，改成**五種能直接跑、或能被機器檢查的檔**，
用一份清單檔 `docs/manifests/<票名>.json` 串起來：

| 種類 | 白話 |
|---|---|
| 生產模組空殼 | 要寫的程式檔先建出來（空的），寫完才算數 |
| 驗收測試／驗收腳本 | 「要驗什麼」直接寫成會跑的測試，不再只是一句話 |
| 契約 JSON | 資料格式的規則，程式讀得懂 |
| 批次卡 | 這批改哪些檔、誰會用到、禁止做什麼、用哪條指令驗 |
| 實跑收據 | 跑過的證據（參考用） |

並加了三道**自動擋**的機制，不靠人記得：

1. **存檔當下就擋散文 TODO**：新票若又寫散文 TODO，存檔那一刻就被擋下，並告訴你該改成哪五種。
   舊票既有的 69 份散文 TODO 照舊可以改，不受影響。
2. **清單檔存檔當下就檢查**：五類欄位齊不齊、列的檔案在不在、「做不到」的理由是不是三種合法值之一……約 0.1 秒。
3. **派工閘門**：新規格書要派工，必須附上對應的清單檔，而且清單檔寫的規格書要對得上，否則不發派工許可。
   我自己實作時領的許可也一樣，必須綁定規格書。

另外，TODO 範本改寫成新格式；CLAUDE.md 與分工手冊裡「TODO 是什麼」改成同一句定義。
**審查強度一個字都沒動**：對抗式審查、實作者不自審、審查家數以分工手冊為準、不得跳步，這四條有測試逐字守著。

## 這票期間查出的真問題（都已修）

1. **檔名裡夾一個換行字元，就能混過檢查**——格式檢查器、存檔守衛、派工閘門各中一次，同一種寫法。
2. **路徑換個寫法就能讓新的散文 TODO 不被擋**（用 `..`、或指向專案的捷徑目錄）。實測發現 Claude 的存檔工具會自動把 `..` 折掉照樣寫入，所以守衛必須用同一種方式解讀路徑。
3. **總驗收只看測試輸出最後三行**，被跳過的測試會被漏看、誤報全過。
4. **驗證用的測試複本少帶了相依檔**，測試因為別的原因變紅，看起來像驗證有效，其實沒驗到。
5. **新規則上線後，另一張舊票有 3 條測試被打紅**——規格要求改閘門時要一起跑舊測試，我第一次提交時漏跑；收尾自查時補跑才發現，已修。
6. **補遺審查抓到：新格式的「延後到某處」檢查會對整份清單檔搜字**，目標只出現在描述欄也會被接受。已改成只認清單檔裡「做不到的項目」那一欄。
