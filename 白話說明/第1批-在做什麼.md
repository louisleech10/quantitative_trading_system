## 為什麼要先做這批

派工單是整條流水線的**輸入**。輸入錯了，後面三家委員全部白跑。

08-04 有一次燒掉 **3 輪**委員——三次都是**機制做對、我的指令下錯**。
委員照著錯的指令做出錯的東西，然後我再花一輪去發現「其實是我寫錯」。

**檢查最少、槓桿最高的地方，就是這裡。**

真正的解法是 `票 B-25` 那套：**判準存成資料檔，文件裡的內容用程式生成，手改就對不上而被擋**。
但那套基礎設施排在這批**後面**。

⇒ 所以這批的每一個判準，我都得**手工想出「怎麼不靠散文表達」**。這是整批成本的主要來源。

## 🔴 B4 階段 2 試做了，被自己的規矩擋回來（2026-08-09）

階段 2 要做的事很單純：**派工的時候如果沒附派工單，就不發通行證**。

我做出來了，而且**功能是對的**：沒附 → 拒發並講清楚是因為沒附派工單；附了 → 正常放行；
把這段檢查關掉 → 兩條測試立刻轉紅（證明它真的在擋）。

**但它打到 31 個既有測試**，橫跨 10 個檔——那些測試本來就直接呼叫派工程式、而且不帶派工單。

問題在於：**那 10 個檔不在這一批「准許改動」的清單裡**。
而要把它們加進清單，會被**我自己在這一批開頭立的守衛**擋下。

⇒ 這就是「**被約束方自己解開約束**」。我對實作端說過不准這樣做，那我自己也不能做。

**所以我撤回了。** 這是這個 epic 第五次「規矩 A 要你做的事、規矩 B 不准你做」。

### 為什麼我沒有硬做下去

因為硬做只有兩條路，兩條都是壞的：
- 把清單偷偷加大 → 就是我禁止別人做的那件事
- 只改測試讓它們別紅 → 那是為了讓燈變綠而改測試，等於自欺

**正確的做法是承認 scope 錯配**：這個改動的影響範圍本來就跨越好幾批，
硬塞進這一批是我一開始就放錯位置了。應該獨立成一張票，讓它自己帶著該有的範圍。

這件事**不擋 B5**，接著往下走。

## 🔨 B5 偵察完成 — 又抓到一次死鎖，這次在動工前（2026-08-09）

B5 要做的三件事之一是：**文件裡寫「全部」「所有」這種話，就得附上一條可以跑的命令來證明**。

問題是——**這個檢查會把這個 epic 自己的規格文件鎖死**。

機制是這樣：派工的時候只要附上規格檔，系統就會拿那份規格去跑格式檢查，**沒過就不發通行證**。
而那份規格是**凍結唯讀**的，裡面有十幾處「全部」「所有」，不可能回去補命令。

⇒ 這個檢查一上線，**所有派工都拒發，而且沒人能派工去修它**。

**這是第六次「規矩 A 要你做的事、規矩 B 不准你做」**——但這次跟前五次不同：
**我們在動工前就抓到了**，不是做完才發現。偵察本身值回票價。

### 一個有意思的細節

我和兩家委員各自數「有幾處違規」，得到**三組不同的數字**（我 16／22、一家 9／17、一家 4／11）。

一開始看起來像有人數錯。但其實不是——**是「什麼才算違規」根本還沒定義**，
所以三個人各寫各的原型，就得到三組數字。

**這個不一致本身就是最重要的發現**：規格說「要檢查全稱詞」，卻沒說清楚什麼算全稱詞。
兩家委員給的修法方向一致：**不要去掃自然語言，改成只認一個明確的欄位**——
這正是這個專案反覆學到的那條「黑名單永遠列不完，要改成封閉集合」。

## 委員可以隨時換了（2026-08-09）

你說委員每週都會加減、換模型、調額度，要能低摩擦地改。做好了兩件事：

**① 換委員 ＝ 改一行**

`scripts/governance_families.json` 裡：

```
"review_families": ["codex", "composer", "grok"],   ← 正式名冊，不動
"active_stampers": ["codex", "composer"]            ← 改這行
```

戳記檢查的**預設值**現在讀第二行，所以所有地方自動生效。
每次 push 都會印「⚠ 委員暫停中（未清）: grok」——不靠任何人記得。

**② 任務中穿插修別的事 ＝ commit 訊息加一行**

```
Governance-Scope: out-of-epic <理由>
```

原本的問題是：epic 進行期間，**整個 repo 被凍住**——任何不在這批宣告清單裡的檔案都不能改，
而那份清單又是從凍結唯讀的規格導出的。所以「治理系統沒辦法修自己」，我一天內撞牆四次。

現在這種 commit 可以豁免，但**凍結規格、清單本身、錨點檔仍然碰不得**，
而且每次 push 都會列出所有這類 commit 供你稽核，不是偷偷放行。

### 委員抓到我一個真的漏洞

我請兩家去攻擊這條新通道，codex 找到一個 **BLOCKING**：

`git diff --name-only` **會隱藏改名前的舊檔名**。所以只要在那種 commit 裡把凍結的規格檔
**改個名字**，系統看到的是新名字（不在保護清單）⇒ 就放行了，等於把保護檔搬走。

已修：只要範圍內有任何改名動到保護檔，**整條豁免直接關閉**。
