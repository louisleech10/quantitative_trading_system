## 🔴 維護規則（使用者 2026-08-05 定）

SYNCED-AT: 29e30660144b3e8aeb54ed38ef70aeedda23fb15

🔴 **上面那行是機器標記，不是裝飾。** `scripts/plain_docs_sync_check.sh` 會比對：
自該 commit 起若有任何改動觸及 `scripts/`／`docs/GOVB0_`／`tests/governance/`，
而本檔**未同步更新** ⇒ **檢查失敗、擋住 push**。

**為什麼要做成機檢**：使用者 2026-08-05 指出「白話說明和日誌你忘記或沒做即時更新，就斷了」。
本專案第 3 條治理原則＝**工具必須自帶強制機制，不准靠紀律和記憶**。
⇒ 這條規則不靠我記得，忘了就會被擋下來。

**誠實邊界**：它只驗「有沒有動」，**不驗內容是否真的反映現況**——
有人可以只改一個字元換綠燈。屬「擋意外不防蓄意」，內容正確性仍靠審查。

### 三條規則本體

1. **時時更新**——每完成一個批次，立刻更新本檔的進度區塊與施工清單的進度表。
   不是等整批做完才更新。
2. **一份做完就封存**——某個任務（如第 0 批）整批完工後，
   把它的說明檔移到 `白話說明/Archived/`，本檔只留**當前正在做的那一個**。
   ⇒ **你打開這個資料夾，看到的永遠是「現在在幹嘛」，不是一堆歷史。**
3. **日誌是我自己的紀錄**——使用者不看流水帳，有問題直接問我。
   我依需要決定是否續寫與分檔，不佔用本檔版面。
