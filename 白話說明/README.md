## 🔴 維護規則（使用者 2026-08-05 定）

🔴 **這幾條不靠我記得——`scripts/plain_docs_sync_check.sh` 會擋。**

判準：**每個說明檔的最後更新，不得早於它所對應的實作／規格路徑的最後改動。**
接在 `scripts/gov_check.sh`（pre-push 的唯一委派點）⇒ **忘記更新就推不上去。**

| 說明檔 | 它監看什麼 |
|---|---|
| `README.md`／`第0批-施工清單.md` | `scripts/`、`docs/GOVB0_`、`tests/governance/` |
| `治理待辦總覽.md` | `handoffs/20260801-GOV-AMEND-BACKLOG.md` |
| `第0批-在做什麼.md` | `docs/GOVB0_FRICTION_SPEC.md` |
| `治理進度日誌.md` | 不受管（使用者明示不看） |

**這個設計被使用者連續打回三次才對**：
①一開始沒有任何檢查 → ②只驗 `README.md`（其他檔忘了也沒事）→
③腳本要「記得跑」才有用（等於把紀律換個地方）→
④判準只驗「有沒有動過」，**實測證偽**：文件先更新、實作後改也算過，**順序完全沒驗**。
現行版本改為**比新舊**，副作用是**連人工標記都不需要了**——少一個要記得維護的東西。

**誠實邊界**：只驗**時序**，**不驗內容是否真的反映現況**——可只改一字換綠燈。
`git push --no-verify` 亦可繞過。屬「擋意外不防蓄意」，內容正確性仍靠審查。

### 三條規則本體

1. **時時更新**——每完成一個批次，立刻更新本檔的進度區塊與施工清單的進度表。
   不是等整批做完才更新。
2. **一份做完就封存**——某個任務（如第 0 批）整批完工後，
   把它的說明檔移到 `白話說明/Archived/`，本檔只留**當前正在做的那一個**。
   ⇒ **你打開這個資料夾，看到的永遠是「現在在幹嘛」，不是一堆歷史。**
3. **日誌是我自己的紀錄**——使用者不看流水帳，有問題直接問我。
   我依需要決定是否續寫與分檔，不佔用本檔版面。
