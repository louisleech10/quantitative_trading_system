## 你的三個症狀，各自是什麼原因

| 你看到的 | 真正的原因 |
|---|---|
| 終端機一直跑不停 | 下載 K 線時，程式往幣安要資料的「時間游標」用**秒**為單位送出，但實際 K 線的時間精度是**毫秒**。小數點被切掉之後，游標永遠停在同一根 K 線上 ⇒ **無窮迴圈**，而且同一根 K 線被重複抓進來（資料會重複） |
| 前端顯示請求超時 | 下載是「同步」動作（會卡住），卻被放在後端的主執行緒上跑 ⇒ **整台後端在下載期間對任何請求都不回應**，前端當然逾時 |
| log 檔什麼都沒有 | 並行搜尋是開子行程做的，而子行程**不會繼承**主行程的日誌設定 ⇒ 所有 worker 的紀錄（包含失敗原因）都沒有寫進檔案 |

## 順便修掉的一個「看起來成功、其實沒資料」的陷阱

原本的程式在下載卡住時會**默默把不完整的資料當成功回傳，還寫進快取**。
這比報錯更糟：你會拿到一份看起來正常、其實少了資料的結果，而且完全看不出來。

現在改成：**資料不完整就整個拒收**，任務會標成「失敗」並告訴你是哪個 symbol 出問題，
而且**不會寫進快取**（避免壞資料污染後續所有分析）。

⚠️ **這是行為改變，你會看到的差別**：
以前遇到這種情況顯示「找不到案例」（你會以為是條件沒中），現在會顯示**錯誤訊息**。
後者才是實話。

## 我犯過最值得記的三個錯

**一、我叫你「重啟後端重跑」，那個建議是錯的**
我第一版只修了「並行」那條路徑。但你只跑 4 個 symbol，數量比 worker 少，
程式會走另一條「串行」路徑——**那條我完全沒修到**，重跑一樣會卡死。
codex 和 grok 各自獨立抓到這件事。

**二、同一條測試我寫了五版，前四版都是空的**
有一條測試負責「掃描全部程式碼，找出會把錯誤吞掉的地方」。
它的判斷範圍我寫錯了四次（打錯函式名、豁免條件太寬、漏掃某種寫法、只檢查名字沒檢查行為），
每一次測試都顯示綠燈，但實際上什麼都沒檢查到。

最後我改了做法：不再「下次更仔細」，而是**讓這條測試自己也被測**
（餵它 11 種已知的規避寫法，每一種都必須被抓到），
並且在程式碼裡**寫死它的能力邊界**——它只能擋「不小心」，擋不住「刻意規避」，
真正的防線是另外七條直接跑真實流程的測試。

**三、我自己訂的蓋章判準，我自己違反**
我在蓋章指令裡寫「每一條殘留事項都要說明為什麼現在不做」，
然後自己把四條殘留擠成一行、一個理由都沒寫。
codex 蓋章時 REJECT 擋下來（另外兩家沒查這條）。已拆成四條逐一補上理由。

## 還沒做的事（每條都說明為什麼現在不做）

| 事項 | 為什麼現在不做 |
|---|---|
| 一個 symbol 失敗時，其他 symbol 的結果照樣回傳 | 目前任務只有「成功／失敗」兩種狀態，要做這個得先加「部分成功」狀態並想好前端怎麼顯示「缺了哪幾個 symbol」，否則你一樣分不清「真的沒信號」還是「資料被拒收」 |
| 把鎖切得更細（現在兩個搜尋會互相等） | 要先定義 HDF5 檔案層級的併發規則，否則單行程的鎖切細了、跨行程照樣壞 |
| 跨行程同時寫同一個 HDF5 檔沒有協調 | 同上，需要先做研究 |
| 「子行程的 log 有沒有真的寫進檔案」這件事**沒有任何環境驗證過** | 三家委員 + 我的環境**全部**因為沙箱權限跑不起子行程，而這個專案已經沒有 CI。**這條我不宣稱已驗證** |
| 幣安「上市日期」快轉（1 分鐘線查上市前一年會多送約 526 次空請求） | 要新增一個資料來源並定義它的時間點契約，且不確定交易所會不會改寫上市時間 |
| 多行程日誌的佇列與輪替 | 正解會動到全域日誌架構，屬於跨模組改動，要先確認父子行程的日誌歸屬 |
| 取消搜尋的語意 | `/search` 目前根本沒有取消的端點，沒有人能觸發那條路徑 |
| 打包佈署時的日誌路徑 | 這個專案沒有打包佈署，依你「面向未來不溯及既往」的裁定不預作 |
