## 三、步驟 1 成果：28 條逐條複核

6/24 之後實際落了**七個**修復 epic（ROADMAP 自己都漏記一個）。複核結果分四類：

### ✅ 已經修好的（不用再做，也別再排程）

| 當年的問題 | 現在的狀態 |
|---|---|
| 顯著性檢定用錯統計假設（把相關序列當獨立） | 改用正確的 HAC 方法，已進主流程 |
| FDR 多重比較防偽是「假開關」（UI 有、後端沒接） | 真的接上了，開關有效 |
| 沒有訓練/測試切分，全部樣本內自我評分 | 切分預設開啟，失敗時會大聲警告 |
| Net IC 公式量綱錯（相關係數減報酬率，數學無意義） | 公式修正，成本參數全棧接通 |
| 因子歸因雷達圖顯示假數字（硬填 NaN 繞過） | 改成誠實顯示「不可用」＋原因 |
| feature_filter 前端送了後端偷偷丟掉 | 已接通，真的會篩 |
| 多處「偷看未來」的洩漏（rolling IC、分位門檻、regime） | 三個 epic 逐一修掉 |

### 🔴 還活著的三個 P0（使用者看得到的錯）

1. **分位數收益圖永遠空白**。後端有算，但資料是「盒子裡再套盒子」的格式，
   前端卻直接找外層盒子裡的數字 → 永遠找不到 → 圖恒空、但旁邊的摘要分數有值。
   這條四方意見分裂（兩家說修好了），Grok 實際跑程式證明沒修，我親自讀碼裁決 Grok 對。
2. **橫截面模式半殘**。切到橫截面分析時，衰減/分位/分組/換手四類資料後端直接回空殼，
   前端顯示「暫無數據」——你分不清是「這模式本來就不算這個」還是「壞了」。
3. **事件分析會靜默騙人**。事件樣本不夠時，系統默默改跑全樣本，畫面不會告訴你。
   你以為在看「事件發生後的 IC」，其實看的是全樣本 IC。另外 API 收了事件時間戳
   但根本沒往下傳（只寫了一行 log）。

### ⚠️ 修了一半／變形的

- **正交化**：現在真的有算殘差（以前只是轉換摘要冒充），但刻意標「僅供研究、禁下游消費」，
  而且前端沒有圖在顯示它——等於算了沒人看。
- **幽靈開關還有一批**：換手率開關關了後端照算（只是前端藏圖）；前端面板有五個設定鍵
  後端根本不讀；兩個設定項（相關性上限 200、Shapley 設定）是「死配置」——寫在設定檔裡但
  程式從來不讀。**這批正是下一步 wiring 閘門要永久防的東西。**
- **一些圖表把「沒資料」畫成 0**，看起來像真的量測到 0——會誤導判讀。

### ❌ 從來沒做的（登記在案，這次不施工）

- 策略層防過擬合三件套（DSR／PBO／MinBTL）——完全沒有
- IC 系統和 ML 系統（XGBoost/SHAP）是兩條平行線，沒有橋
- 多因子組合 IC／邊際 IC（回答「這因子有沒有帶來新資訊」）——沒有
- Pooled/Panel 縱橫混合 IC——沒有
- 容量/滑價估計——缺成交量資料源，只有空殼

## 四、步驟 1 成果：接線盤點（哪些算了沒人看、哪些看了沒在算）
