## 🔴 清單為什麼審了 12 輪

清單是**寫給實作端照著做的施工說明書**，每一條驗收都會變成閘門。
**閘門寫錯的代價不是慢，是它會亮綠燈但什麼都沒擋。**

### 兩個最致命的（都是委員抓的，我自己沒看出來）

| 委員抓到 | 白話 |
|---|---|
| 某個檢查**由構造上永遠通過** | 我寫「把宣告過的檔複製到乾淨資料夾，再比對差異」——複製進去的只有宣告過的東西，**差異永遠是空的**。那個檢查存在，但什麼都不擋 |
| 新加的閘門**永遠不會被執行** | 我加了參數卻沒接線，**既有呼叫從來不帶那個參數** ⇒ 斷言全綠、生產零保護。跟先前「檢查程式沒有任何人呼叫」是同一個病 |

### 收斂軌跡

```
相異問題數：7 → 4 → 4 → 2 → 3 → 4 → 5 → 3 → 4 → 3 → 1 → 0(三家蓋章)
```

件數在震盪，但**每一輪打的位置越來越深**，而且**方向裁定連八輪沒被質疑**——
被打的一直是我的落地細節，不是設計方向。

### 一個判準換了五版才過

「哪些檔案要被檢查」這一個問題：

```
① 掃文件的「驗收區塊」   → 區塊種類可以無限長出第 N 類
② 檔名樣式 ∪ 抓呼叫字串  → 用變數組出來的路徑抓不到
③ 表格加一個分類欄       → 分類掛在「列」上不是「路徑」上，同一路徑掛兩列就不明
④ 白名單 ∩ 副檔名        → 副檔名也是列舉，沒副檔名的就漏掉
⑤ 白名單裡明列「這是要檢查的」 ← 現行
```

「改動範圍怎麼算」換了三版：全樹比對（被既有髒檔卡死）→ 乾淨沙箱複製（**恆空**）→ 只看提交範圍。

### 這一段的三個教訓

**1. 委員開的藥方，也要先查能不能吃**

照著派下去那輪保證失敗。規矩已改成雙向適用：**採信委員修法前也要窮舉**。

**2. 修東西會修出新東西**

第一輪修補**自己造成一個新缺陷**：刪程式時把跟著的清理動作一起刪了，
變成每派一次工漏兩個暫存檔。**委員抓的，我看 diff 沒看出來。**
所以第二輪 review 我把火力全放在「修法有沒有又弄壞別的」——四個問題收斂到一個。

**3. 事實可以接受，藥方可以拒絕**

最後一個問題我**接受委員的事實、否決委員的藥方**，理由寫清楚送回去，
**指名要提出的那家表態**。它回覆拒絕成立，並自己改良了藥方。

這比「委員說什麼就做什麼」和「我說了算」都好——**分歧看碼證，不看誰先講**。

### 第 4 輪那件事值得單獨講

我正在寫一份文件、要委員去測「這條規則會不會誤擋」，**結果那份文件當場被這條規則擋下**——
而它只是在**討論**這條規則，不是真的在宣稱數字。

根因是：規則用「整行任何位置有沒有出現關鍵字」來挑要檢查的行，
**沒有分辨「這是宣告」還是「這是在講這件事」**。

同一份規格文件裡，另一條規則早就寫過這個教訓，**這條沒套用**。

### 第 5 輪：修窄了，反而漏掉該擋的

我把選取範圍收窄之後，`1.`、`>`、`**粗體**`、`+` 開頭的合法寫法**從此都不受檢查**，
還有：**一個沒閉合的程式碼區塊，會讓整份文件後半完全不被檢查**。

**收窄型的修法，風險方向是反的**——不是誤擋，是該擋的不擋了。
這條已經寫成通則，之後每次做收窄修法都要照著查。

### 停損機制第一次真的用上

第 2 輪時我先寫死一條規則：**如果後面幾輪還在同一個地方抓到「更刁鑽的同類變體」，
就判定為無限追逐，轉成具名記錄、不再開新輪。**

後來委員每個 finding 都要自己標「新類別／同類變體／修法造成的」。結果：

- **同類變體** ⇒ 照規則轉記錄，不修
- **修法造成的** ⇒ 無例外必修
- **新類別** ⇒ 逐案判

**沒有變成無限迴圈。** 這是這個機制第一次實際運作。
